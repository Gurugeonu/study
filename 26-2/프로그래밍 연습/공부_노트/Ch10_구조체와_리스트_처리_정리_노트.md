# Ch10 구조체와 리스트 처리 정리 노트

> 범위: A p2–34 · 출처 약어: A = chap10. Structures and List Processing.pdf
> 단원 요약 항목: 자기 참조 구조체 · 선형/단일 연결 리스트 · 리스트 처리 · 스택 · C의 불리언 타입 · 연결 리스트 변형 [A p34]

## 1. 핵심 개념
- **자기 참조 구조체(self-referential structure)**: 자기와 같은 구조체 타입을 가리키는 포인터 멤버를 하나 이상 가진 구조체. [A p2]
  ```c
  struct node { int data; struct node *next; };   // next = 링크(link)
  typedef struct node { ... } Node;               // typedef 별칭
  ```
- **자기 참조 구조체의 장점**: 연결 리스트·트리·그래프 같은 동적 자료구조 생성, 노드 개수 제한 없음(유연·확장 가능), 포인터로 이어진 탐색 가능한 사슬. [A p3]
- **선형 연결 리스트(linear linked list)**: 노드를 일직선(비순환)으로 나열한 것. [A p6]
  - `head` 포인터 = 첫 원소의 주소 / 각 원소가 다음 원소와 연결 / 마지막 원소의 링크 = `NULL`
  - 슬라이드 그림: 단일 연결(n→e→w)과 양방향 연결(12⇄99⇄37) 모두 "선형" 예시 → 선형 = 원형이 아님
- **리스트 기본 연산 6가지**: 생성, 개수 세기, 원소 찾기, 두 리스트 연결, 삽입, 삭제. [A p11] (원소 찾기는 목록에만 있고 코드 없음)
- **스택(stack)**: LIFO(Last In, First Out). 마지막에 push한 원소를 가장 먼저 pop. [A p25]

| 스택 연산 | 동작 |
|---|---|
| `push(data)` | 맨 위에 놓기 |
| `pop()` | 맨 위 원소 제거 후 반환 |
| `top()` | 맨 위 원소를 제거하지 않고 반환 |
| `isEmpty()` | 비었는지 검사 (예제 구현엔 `isFull()`도 있음) |

- **스택 사용처**: 호출 스택, 실행 취소(undo) 기록, 구문 분석(여는 `( [ {` push → 닫는 괄호마다 pop해 짝 확인). [A p25]
- **도달 불가 노드(unreachable node)**: 가리키는 포인터가 없어 영영 해제할 수 없는 노드 → 메모리 누수(memory leak). [A p21]
- **매달린 포인터(dangling pointer)**: 이미 해제된 메모리 주소를 계속 들고 있는 포인터. 예: `free(temp)` 뒤의 `temp`. [A p21]
- **연결 리스트 변형** [A p33]

| 종류 | 구조 |
|---|---|
| 단일 연결(singly) | 다음 포인터 하나, 마지막 `NULL` |
| 양방향 연결(doubly) | 이전·다음 포인터 둘, 양 끝 `NULL` |
| 원형 연결(circular) | 마지막 노드가 첫 노드를 가리킴(`NULL` 없음) |

## 2. 핵심 코드 (형식·관용구)
| 목적 | 핵심 줄 | 비고 |
|---|---|---|
| 리스트 타입 (`list.h`) | `typedef char DATA;` `struct node { DATA d; struct node *next; };` `typedef struct node ELEMENT;` `typedef ELEMENT *LINK;` | `LINK` = `ELEMENT *` [A p7] |
| 노드 할당 | `head = malloc(sizeof(ELEMENT)); if (head == NULL) exit(EXIT_FAILURE);` | 할당마다 NULL 검사 [A p8] |
| 정적 노드 연결 | `a.next = &b; b.next = &c;` → `a.next->next->data`는 c의 값 | [A p4–5] |
| 반복 생성 (`s_to_l`) | `tail->next = malloc(...); tail = tail->next; tail->d = s[i];` 끝에 `tail->next = NULL;` | 빈 문자열 → `NULL` 반환 [A p12] |
| 재귀 생성 (`string_to_list`) | 기저: `s[0]=='\0'` → `NULL` / `head->d = s[0]; head->next = string_to_list(s + 1);` | [A p14] |
| 반복 개수 (`count_it`) | `for ( ; head != NULL; head = head->next) ++cnt;` | [A p15] |
| 재귀 개수 (`count`) | `NULL` → 0 / `return 1 + count(head->next);` | [A p16] |
| 연결 (`concatenate`) | `if (a == NULL) return b; a->next = concatenate(a->next, b); return a;` | 둘 다 빈 리스트 가능 [A p17] |
| 재귀 처리 일반형 | `if (head == NULL)` 기저 / `else` head 처리 → `f(head->next)` | [A p18] |
| 삽입 (`insert`) | `assert(p1->next == p2); p1->next = q; q->next = p2;` | 연속한 두 노드 사이 [A p20] |
| 삭제 (`delete`) | `if (p != NULL && p->next != NULL) { temp = p->next; p->next = p->next->next; free(temp); }` | `p` **다음** 노드 삭제 [A p22] |
| 전체 삭제 재귀 | `delete_list(head->next); free(head);` | 후위(post-order): 재귀 호출 **뒤** 해제 [A p23] |
| 전체 삭제 반복 | `next = current->next; free(current); current = next;` | [A p24] |
| 스택 타입 (`stack.h`) | `struct elem { data d; struct elem *next; };` `struct stack { int cnt; elem *top; };` `#define EMPTY 0` `#define FULL 10000` | 조회 함수 인자는 `const stack *` [A p27] |
| `initialize` | `stk->cnt = 0; stk->top = NULL;` | [A p28] |
| `push` | `p->d = d; p->next = stk->top; stk->top = p; stk->cnt++;` | malloc + NULL 검사 먼저 [A p28] |
| `pop` | `d = stk->top->d; p = stk->top; stk->top = stk->top->next; stk->cnt--; free(p); return d;` | 비었으면 `exit` (언더플로) [A p29] |
| `top` | `return stk->top->d;` | 비었으면 `exit` (언더플로) [A p30] |
| `isEmpty` / `isFull` | `return (bool)(stk->cnt == EMPTY);` / `(stk->cnt == FULL)` | [A p30] |

## 3. 원리·결론
- `malloc`은 `void *` 반환. C에서는 `void *`가 객체 포인터로 자동 변환 → 캐스트 불필요. C++은 암시적 변환 없음 → 캐스트 필요. [A p8]
- 삽입 시간: 연결 리스트 $O(1)$(위치가 이미 정해진 경우), 배열 평균 $O(n)$(뒤 원소를 한 칸씩 이동, $n$ = 배열 원소 수). [A p19]
- 리스트 재귀: 빈 리스트(`NULL`)가 기저, `head->next`가 더 작은 부분 문제. [A p18]
- 호출 스택: 함수 호출 시 스택 프레임이 쌓이고 반환 시 제거. 스택은 높은 주소 → 낮은 주소로 자람. [A p26]
- 32비트 x86 Linux 메모리 배치(위 → 아래) [A p26]

| 영역 | 내용 |
|---|---|
| 커널 공간 (`0xC0000000`~`0xFFFFFFFF`, 1 GB) | 사용자 코드 접근 불가 |
| 스택 ↓ | 지역 변수, 반환 주소 |
| (unused) | 스택과 힙 사이 빈 공간 |
| 힙 ↑ | `malloc` / `free` |
| BSS | 초기화하지 않은 static 변수 |
| Data | 초기화한 static 변수 |
| Text (`0x08048000`~) | 기계어 명령, 읽기 전용 |
| Reserved (`0x00000000`~) | 매핑 안 됨, NULL 포인터 접근 시 오류 |
- 사용자 영역 3 GB + 커널 1 GB.
- `==`의 결과는 `int`(0 또는 1). `(bool)` 캐스트로 반환 타입을 명시. [A p30]
- **bool**: C99에서 도입된 `_Bool`의 매크로. `_Bool`은 0(false)과 1(true)만 담는 C99 키워드. [A p31]
  - C99–C17: `<stdbool.h>` 포함 필요 (`bool`→`_Bool`, `true`→1, `false`→0, `__bool_true_false_are_defined`→1)
  - C23: `bool`, `true`, `false`가 키워드 → 헤더 불필요
  - 장점: 1/0 대신 true/false로 코드가 명확, 논리식 의도가 드러남

## 4. 문제 유형별 접근
- 리스트 따라가기 출력: `->`를 왼쪽부터 하나씩 따라가며 어느 노드인지 추적
- 반복 생성: 첫 노드 따로 만들기 → `tail = head` → 루프에서 `tail->next` 할당·`tail` 이동·값 저장 → 끝에 `NULL`
- 재귀 함수 작성: 빈 리스트 기저 → head 처리 → `head->next`로 재귀
- 중간 삽입: 앞 노드 `p1`이 `q`를 가리키게 → `q`가 뒤 노드 `p2`를 가리키게
- 중간 삭제: 지울 노드를 `temp`에 저장 → 앞 노드 링크로 건너뛰기 → `free(temp)`
- 전체 삭제: 다음 노드 주소를 먼저 확보한 뒤 현재 노드 해제
- 스택 출력 추적: 넣은 순서의 역순으로 나옴 (예: 문자열 push 후 전부 pop → 문자열 뒤집기)

## 5. 실수 포인트
- `p->next = p->next->next;`만 하면 건너뛴 노드가 도달 불가 → 메모리 누수. 반드시 `temp`로 잡아 `free`.
- 전체 삭제에서 `free(current)` 후 `current->next` 접근 금지 → `next`를 **먼저** 저장.
- 재귀 전체 삭제는 재귀 호출 **뒤에** `free(head)` (먼저 해제하면 `head->next`를 읽을 수 없음).
- 삽입 순서: 미리 `p1->next == p2`인지 확인(`assert`).
- 반복 생성에서 마지막 `tail->next = NULL;` 빠뜨리면 링크가 미정(?) 상태.
- `malloc` 결과는 매번 `NULL` 검사.
- `pop`·`top`은 빈 스택이면 언더플로 → 먼저 `isEmpty` 검사.
- `push`는 내부에서 `isFull`을 검사하지 않음 → 호출 측에서 `if (!isFull(stk)) push(d, stk);`
- `delete(p)`는 `p` 자신이 아니라 `p` **다음** 노드를 지움.
