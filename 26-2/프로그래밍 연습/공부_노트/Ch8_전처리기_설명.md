## 이야기의 시작: 민지의 원고와 편집 비서

민지가 C로 프로그램을 쓰고 있어요. 민지가 쓴 코드는 곧장 컴파일러에게 가지 않아요. 그 사이에 **편집 비서** 한 명이 있어서, 원고를 먼저 받아 "찾아 바꾸기"를 하고, 다른 문서를 끼워 넣고, 필요 없는 쪽은 빼낸 다음 깨끗한 원고만 컴파일러에게 넘겨요. 이 단원 전체가 이 비서가 하는 일들이에요. 이 비유를 끝까지 써 볼게요.

## 1. 전처리기와 지시문: 비서에게 남기는 쪽지

**왜 필요할까요?** 민지는 `3.14`를 코드 여기저기에 직접 쓰기 싫고, `printf` 같은 표준 함수의 선언 800줄을 직접 베껴 쓰기도 싫어요. 누군가 대신 채워 주면 좋겠죠. C는 이 일을 **전처리기(preprocessor)**에게 맡겨서 언어의 기능과 표기를 넓혀요. [A p2]

**정의:** 전처리기는 컴파일 전에 소스 코드를 바꾸는 단계예요. 민지가 비서에게 남기는 쪽지가 **전처리기 지시문(preprocessor directive)**이고, `#`로 시작하는 줄이 바로 그것이에요. 지시문은 컴파일러가 아니라 전처리기와 대화해요. [A p2]

원본의 전후 비교를 보면 비서가 한 일이 그대로 보여요. [A p2]

```c
#include <stdio.h>
#define PI 3.14
    printf("%f\n", PI);
```

전처리 뒤 컴파일러가 보는 모습은 이래요.

```c
/* contents of stdio.h (~800 lines) */
    printf("%f\n", 3.14);
```

`#include` 줄은 stdio.h의 내용(약 800줄)으로 통째로 바뀌었고, `#define` 줄은 사라지면서 `PI`가 `3.14`로 바뀌었어요. 컴파일러는 `PI`라는 이름을 본 적도 없어요.

그런데 비서는 `stdio.h`라는 문서를 **어디서** 찾아올까요?

## 2. `#include`: 문서를 어느 서랍에서 꺼낼까

**왜 필요할까요?** 끼워 넣을 문서는 두 종류예요. 표준 라이브러리 헤더처럼 시스템이 가진 문서와, 민지가 직접 만든 헤더예요. 둘의 보관 장소가 달라서 비서에게 어느 쪽부터 찾을지 알려 줘야 해요.

**정의와 규칙:** [A p3]
- `#include <stdio.h>`처럼 꺾쇠를 쓰면, 비서는 시스템이 정한 여러 위치를 찾아요. **현재 디렉터리는 찾지 않아요.**
- `#include "filename"`처럼 따옴표를 쓰면, **현재 디렉터리부터** 찾고, 없으면 시스템이 정한 다른 위치로 넘어가요.

표준 헤더가 보관된 위치는 시스템마다 달라요. Linux(GCC)는 `/usr/include/`, `/usr/include/x86_64-linux-gnu/`, `/usr/local/include/`이고, macOS(Clang)는 `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/`, Windows(MSVC)는 `C:\Program Files\Microsoft Visual Studio\2022\…\MSVC\<version>\include\`예요. [A p3]

**언제 무엇을 쓸까요?** 표준 헤더는 `<…>`, 민지가 만든 헤더는 `"…"`를 써요. 직접 만든 헤더를 `<…>`로 부르면 현재 디렉터리를 건너뛰어서 못 찾을 수 있어요.

문서를 끼워 넣는 법은 알았어요. 이번엔 비서의 주특기인 "찾아 바꾸기"를 자세히 볼까요?

## 3. `#define`과 객체형 매크로: 단어를 값으로 바꾸기

**왜 필요할까요?** 원주율, 광속, 정수 최댓값 같은 숫자가 코드에 맨몸으로 흩어져 있으면 무슨 뜻인지 읽기 어렵고, 값을 바꿀 때 전부 찾아 고쳐야 해요.

**정의:** [A p5]

```c
#define identifier token_string_opt
```

비서는 이 줄 **아래 파일 나머지 부분**에서 `identifier`가 나올 때마다 `token_string`으로 바꿔요. 단, **따옴표 문자열과 주석 안은 건드리지 않아요.** 그래서 `printf("PI")`의 `PI`는 그대로 남아요. 아래 첨자 `opt`는 token_string을 생략할 수 있다는 뜻이에요.

원본에 나온 예는 이래요. [A p5]

```c
#define PI      3.14159
#define C       299792.458  /* speed of light in km/sec */
#define EOF     (-1)        /* typical end-of-file value */
#define MAXINT  2147483647  /* largest 4-byte integer */
```

하루의 초 수 `(60*60*24)`도 같은 식으로 이름을 붙이는데, 원본은 그 이름을 `SECONDS_PER-DAY`라고 적었어요. 하이픈(`-`)은 식별자에 쓸 수 없으니 `SECONDS_PER_DAY`의 오타로 보는 게 맞아요.

이렇게 값처럼 보이는 매크로를 **객체형 매크로(object-like macro)**라고 해요. 쓰는 자리에서 데이터 객체처럼 보이기 때문이에요. `#define PI 3.14159`가 대표예요. [A p4]

**좋은 점:** 단순한 `#define`만으로도 프로그램의 **명확성(clarity)**과 **이식성(portability)**이 좋아져요. [A p5] `MAXINT`처럼 이름을 보면 뜻이 보이고, 다른 시스템으로 옮길 때 `#define` 한 줄만 고치면 되니까요.

**문법 설탕(syntactic sugar):** 찾아 바꾸기는 숫자만 바꾸는 게 아니에요. C 문법 자체를 취향에 맞게 바꿀 수도 있어요. [A p6]

```c
#define EQ   ==
#define AND  &&
#define OR   ||
#define NOT  !
while (i EQ 1)            /* ⇒ while (i == 1) */
if (x > 0 AND NOT done)   /* ⇒ if (x > 0 && ! done) */
```

비서 입장에선 `EQ`라는 글자를 `==`라는 글자로 바꿨을 뿐이에요.

그런데 이번엔 매번 다른 값을 넣어서 바꾸고 싶다면 어떻게 될까요?

## 4. 함수형 매크로: 빈칸이 있는 찾아 바꾸기

**왜 필요할까요?** 민지는 `a*a`, `(b+1)*(b+1)`처럼 제곱을 여러 번 써요. "무언가의 제곱"이라는 틀을 한 번 정해 두고 빈칸만 바꿔 끼우고 싶어요.

**정의:** 이름 뒤에 괄호로 매개변수를 붙이면, 함수 호출처럼 보이고 인자를 받는 **함수형 매크로(function-like macro)**가 돼요. [A p4, p7]

```c
#define identifier(identifier, …, identifier) token_string_opt
#define SQ(x)  ((x) * (x))
```

여기서 꼭 기억할 점은, 비서가 **계산을 하지 않고 글자만 붙여 넣는다**는 거예요. `SQ(7 + w)`를 보면 `x` 자리에 `7 + w`라는 글자를 그대로 넣어요.

### 괄호가 왜 두 겹이나 필요할까

괄호를 하나씩 빼 보면서 무엇이 깨지는지 따라가 볼게요. [A p7]

**(1) 완전 괄호화 `((x) * (x))`**
- `SQ(7 + w)` → `((7 + w) * (7 + w))`. `x` 자리마다 괄호가 있어서 덧셈이 먼저 묶여요.
- `SQ(SQ(*p))`는 바깥 SQ부터 펼쳐요. `x` = `SQ(*p)`이니 `((SQ(*p)) * (SQ(*p)))`가 되고, 남은 `SQ(*p)`를 다시 펼쳐 `((((*p) * (*p))) * (((*p) * (*p))))`가 돼요.
- 어떤 인자를 넣어도 의도한 대로 계산돼요.

**(2) 인자에 괄호 없음 `#define SQ(x) x * x`**
- `SQ(a + b)`에서 `x` 자리에 `a + b`를 글자 그대로 넣어요 → `a + b * a + b`.
- 컴파일러는 곱셈을 먼저 하니까 → $a + (b \cdot a) + b$.
- 원했던 $((a+b)\cdot(a+b))$와 달라요. 인자 쪽 괄호가 인자를 한 덩어리로 묶어 주는 역할이었던 거예요.

**(3) 본문 전체에 괄호 없음 `#define SQ(x) (x) * (x)`**
- `4 / SQ(2)` → `4 / (2) * (2)`.
- `/`와 `*`는 우선순위가 같아서 왼쪽부터 계산해요 → $(4/2) \cdot 2 = 4$.
- 원했던 $4/((2)\cdot(2)) = 1$이 아니에요. 바깥 괄호는 매크로 결과 전체를 바깥 연산자로부터 지켜 줘요.

**문제 풀이 순서:** 매크로 전개 문제는 ① 인자를 글자 그대로 붙여 넣고 ② 괄호는 정의에 있는 것만 남긴 뒤 ③ 연산자 우선순위대로 계산하면 돼요.

괄호는 챙겼어요. 그런데 정의를 적는 손끝에서 생기는 실수도 있어요.

## 5. 함수형 매크로의 흔한 실수 두 가지

원본은 인자 있는 매크로를 정의할 때 흔한 실수 두 가지를 짚어요. [A p8]

**(1) 이름 뒤 공백**

```c
#define SQ (x)  ((x) * (x))
SQ(7)          /* ⇒ (x)  ((x) * (x)) (7) */
```

비서는 이름 바로 뒤에 `(`가 붙어 있을 때만 "빈칸 있는 틀"로 알아봐요. `SQ`와 `(` 사이에 공백이 있으니 `SQ`는 **객체형 매크로**가 되고, 바꿀 내용은 `(x)  ((x) * (x))` 전체가 돼요. 그래서 `SQ(7)`의 `SQ`만 그 글자로 바뀌고 `(7)`은 뒤에 그대로 남아요.

**(2) 본문 끝 세미콜론**

```c
#define SQ(x)  ((x) * (x));
x = SQ(y);         /* ⇒ x = ((y) * (y));;   빈 문장 */
if (SQ(x) > 10)    /* ⇒ if (((x) * (x)); > 10)   오류 */
```

문장으로 쓸 때는 `;;`가 되어 빈 문장 하나가 더 생길 뿐이라 해가 없어요. 하지만 식 안에서 쓰면 조건식 한가운데 `;`가 끼어들어 문법 오류가 나요. 매크로 본문 끝에는 세미콜론을 붙이지 않아요.

실수를 피하는 법까지 알았으니, 매크로가 실제로 어디에 쓰이는지 볼까요?

## 6. 함수 대신 매크로: 호출 없이 바로 끼워 넣기

**왜 쓸까요?** 함수를 호출하면 인자를 넘기고 돌아오는 비용, 즉 **함수 호출 오버헤드(function call overhead)**가 들어요. 매크로는 비서가 코드를 그 자리에 바로 펼쳐 넣으니(인라인 코드) 이 비용이 없어서 더 효율적이에요. 그래서 매크로는 함수 호출을 대신하는 데 자주 쓰여요. [A p9]

```c
#define min(x, y)  (((x) < (y)) ? (x) : (y))
m = min(u, v);     /* ⇒ m = (((u) < (v)) ? (u) : (v)); */
#define min4(a, b, c, d)  min(min(a, b), min(c, d))
```

`min4`는 매크로 안에서 다른 매크로 `min`을 써서 네 값 중 최솟값을 구해요. 둘씩 짝지어 작은 쪽을 고르고, 그 둘 중 다시 작은 쪽을 고르는 방식이에요.

매크로 본문에는 **함수와 다른 매크로를 모두** 쓸 수 있어요. [A p9]

```c
#define SQ(x)     ((x) * (x))
#define CUBE(x)   (SQ(x) * (x))
#define F_POW(x)  sqrt(sqrt(CUBE(x)))  /* fractional power: 3/4 */
```

`F_POW`가 왜 $\tfrac{3}{4}$제곱인지 한 단계씩 볼게요.
1. `CUBE(x)`는 `SQ(x) * (x)`, 즉 $x^2 \cdot x = x^3$이에요.
2. 제곱근은 $\tfrac12$제곱이니 `sqrt(CUBE(x))`는 $(x^3)^{1/2}$예요.
3. 한 번 더 제곱근을 씌우면 $\left((x^3)^{1/2}\right)^{1/2} = x^{3 \cdot \frac12 \cdot \frac12} = x^{3/4}$예요.

여기서 `sqrt`는 매크로가 아니라 함수예요. 비서는 `CUBE`와 `SQ`만 펼치고 `sqrt`는 그대로 둬요.

그런데 민지가 이미 쓰고 있는 표준 라이브러리에도 이런 매크로가 숨어 있을까요?

## 7. stdio.h와 ctype.h 속의 매크로

**stdio.h의 문자 입출력:** 민지가 매일 쓰던 `getchar`와 `putchar`도 사실 매크로예요. [A p10]

```c
#define getchar()   getc(stdin)
#define putchar(c)  putc((c), stdout)
```

`getchar()`는 "표준 입력에서 한 글자 읽기", `putchar(c)`는 "표준 출력에 한 글자 쓰기"를 짧게 부르는 이름이에요. `putchar`의 `(c)`에도 4절에서 본 인자 괄호가 붙어 있어요.

**ctype.h의 문자 검사:** 조건이 맞으면 **0이 아닌 값(참)**을 돌려줘요. [A p10]
- `isalpha(c)` 문자, `isupper(c)` 대문자, `islower(c)` 소문자
- `isdigit(c)` 숫자, `isalnum(c)` 문자나 숫자, `isxdigit(c)` 16진 숫자
- `isspace(c)` 공백 문자, `ispunct(c)` 구두점
- `isprint(c)` 출력 가능한 문자, `isgraph(c)` 출력 가능하지만 공백은 아닌 문자
- `iscntrl(c)` 제어 문자, `isascii(c)` ASCII 코드(비표준)

`iscntrl`이 참이 되는 **제어 문자(control character)**는 화면에 글자로 찍히지 않고 동작을 시키는 문자예요. 원본 표의 순서대로 이름·코드·C 표기·뜻을 이으면 NUL(0x00, `'\0'`, 널 문자), BEL(0x07, `'\a'`, 경고음), BS(0x08, `'\b'`, 백스페이스), HT(0x09, `'\t'`, 수평 탭), LF(0x0A, `'\n'`, 줄바꿈), VT(0x0B, `'\v'`, 수직 탭), FF(0x0C, `'\f'`, 새 페이지), CR(0x0D, `'\r'`, 캐리지 리턴), ESC(0x1B, `'\x1B'`, 이스케이프)예요. [A p10]

**ctype.h의 문자 변환:** [A p11]
- `toupper(c)`: 대응하는 대문자 값. 바꿀 대문자가 없으면 `c` 그대로.
- `tolower(c)`: 대응하는 소문자 값. 없으면 `c` 그대로.
- `toascii(c)`(비표준): 대응하는 ASCII 값.

**조건:** `c`는 `char`나 `int` 같은 정수형 변수예요. 그리고 메모리에 저장된 `c`의 값은 **바뀌지 않아요.** 결과는 새 값으로 나올 뿐이라 `c = toupper(c);`처럼 받아서 써야 해요. [A p11]

매크로가 함수처럼 "값을 반환한다"고 흔히 말하지만, 이건 비공식 표현이에요. 실제로는 비서가 펼쳐 넣은 식이 계산되어 어떤 값이 되는 것뿐이에요. [A p11]

지금까지 비서는 바꾸고 끼워 넣기만 했어요. 이번엔 원고의 일부를 **아예 빼 버리면** 어떨까요?

## 8. 조건부 컴파일: 조건에 따라 쪽을 넣고 빼기

**왜 필요할까요?** 민지는 개발 중에는 변수 값을 찍어 보는 디버그 출력을 넣고, 완성본에서는 빼고 싶어요. 또 컴퓨터 종류마다 다른 코드를 넣어야 할 때도 있어요. 매번 코드를 지웠다 살렸다 할 순 없죠. 그래서 비서에게 "이 조건이면 이 부분을 원고에 넣고, 아니면 빼라"고 시키는 것이 **조건부 컴파일(conditional compilation)**이에요.

**지시문들:** [A p12]
- `#if expr`: expr이 0이 아니면 블록을 컴파일해요. 예 `#if DEBUG`
- `#ifdef name`: name이 정의되어 있으면 컴파일해요. 예 `#ifdef DEBUG`
- `#ifndef name`: name이 정의되어 있지 **않으면** 컴파일해요. 예 `#ifndef MYHEADER_H`
- `#elif expr`: else-if처럼 다른 조건을 검사해요. 예 `#elif defined(SUN4)`
- `#else`: 앞의 어떤 분기도 맞지 않을 때 컴파일해요.
- `#endif`: 조건 블록을 끝내요.
- `defined(name)`: `#if` 안에서 쓰며, name이 정의되어 있으면 1, 아니면 0이에요. 예 `#if defined(A) && !defined(B)`
- `#undef name`: 매크로 정의를 지워요. 예 `#undef DEBUG`

이제 원본의 세 가지 쓰임을 차례로 볼게요. [A p13]

### 디버그 플래그

```c
#define DEBUG 1
#if DEBUG        /* tests the value */
    printf("debug: a=%d\n", a);
#endif
```

```c
#define DEBUG    /* just a flag */
#ifdef DEBUG     /* tests if defined */
    printf("debug: a=%d\n", a);
#endif
```

두 방식의 차이가 핵심이에요. **`#if`는 매크로의 값을, `#ifdef`는 정의되어 있는지만** 봐요. 첫 번째는 `DEBUG`가 1이라 켜지고, 0으로 바꾸면 꺼져요. 두 번째는 `DEBUG`에 값이 없어도 정의만 되어 있으면 켜져요.

코드를 한 글자도 고치지 않고 플래그를 켜는 방법도 있어요. 컴파일할 때 `gcc -DDEBUG main.c`라고 치면 돼요. [A p13]

> 보충: `-DDEBUG`는 소스 맨 앞에 `#define DEBUG 1`을 넣은 것과 같아서, `#if DEBUG`와 `#ifdef DEBUG` 둘 다 켜져요.

### 플랫폼별 코드

```c
#if defined(HP9000) || \
    (defined(SUN4) && !defined(VAX))
    /* machine-dependent code */
#endif
```

"HP9000이거나, SUN4이면서 VAX는 아닌 기계"일 때만 이 코드를 넣어요. 줄 끝의 `\`는 지시문을 다음 줄로 이어 쓴다는 표시예요. 원본은 `&&`가 `||`보다 더 강하게 묶이므로(우선순위가 높으므로) 둘째 줄의 괄호는 없어도 뜻이 같다고 짚어요. 괄호는 읽는 사람을 위해 넣은 거예요. [A p13]

### 헤더 가드

```c
#ifndef MYHEADER_H
#define MYHEADER_H
    /* declarations */
#endif
```

**헤더 가드(header guard)**는 같은 헤더가 두 번 포함되는 걸 막아요. [A p13] 순서대로 따라가 볼게요.
1. 처음 포함될 때는 `MYHEADER_H`가 정의되어 있지 않으니 `#ifndef`가 참이에요. 안으로 들어가요.
2. 바로 `MYHEADER_H`를 정의하고, 선언들을 원고에 넣어요.
3. 두 번째로 포함될 때는 이미 `MYHEADER_H`가 정의되어 있으니 `#ifndef`가 거짓이에요. `#endif`까지 통째로 건너뛰어요.

> 보충: 같은 구조체 정의 등이 두 번 들어가면 "중복 정의" 컴파일 오류가 날 수 있어서 헤더 가드가 필요해요.

원고를 넣고 빼는 법까지 익혔어요. 그런데 비서가 처음부터 알고 있는 단어도 있을까요?

## 9. 미리 정의된 매크로: 비서가 원래 아는 단어

**왜 필요할까요?** 디버그 메시지에 "몇 번째 줄, 어느 파일, 어느 함수"를 찍고 싶을 때, 민지가 줄 번호를 손으로 적으면 코드가 바뀔 때마다 틀려져요. 컴파일러가 이런 정보를 **미리 정의된 매크로(predefined macro)**로 알려 줘요. [A p14]

- `__DATE__`: 파일을 컴파일한 날짜, `"Mmm dd yyyy"` 형식. 예 `"Mar 15 2023"`
- `__TIME__`: 컴파일한 시각, `"hh:mm:ss"` 형식. 예 `"14:20:50"`
- `__STDC__`: 컴파일러가 ISO C 표준을 따르는지 알려 줘요. 따르면 `1`
- `__FILE__`: 지금 컴파일 중인 파일 이름. 예 `"my_program.c"`
- `__LINE__`: 이 매크로가 놓인 소스 파일의 줄 번호. 50번 줄이면 `50`

`__func__`는 조금 달라요. 매크로가 아니라 C99 이후(그리고 C++)에 있는 특별한 **미리 정의된 식별자(predefined identifier)**예요. 함수 안에서 쓰면 그 함수 이름을 담은 문자열 리터럴이 돼요. [A p14]

**예제:** 원본은 이 셋을 묶은 디버그 매크로를 만들어요. [A p15]

```c
#define DEBUG_PRINT(msg) \
    printf("DEBUG: File: %s, Line: %d, Function: %s, Message: %s\n", \
           __FILE__, __LINE__, __func__, msg)
        DEBUG_PRINT("x is less than 10");
```

출력은 `DEBUG: File: my_program.c, Line: 8, Function: main, Message: x is less than 10`이에요.
1. 매크로 정의가 길어서 줄 끝의 `\`로 여러 줄에 이어 썼어요.
2. `main` 안에서 `x = 5`이고 `x < 10`이 참이라 위의 `DEBUG_PRINT`가 실행돼요.
3. 원본 프로그램에서 이 호출은 8번째 줄에 있어요(`#include`가 1번째 줄). `__LINE__`은 매크로를 **정의한** 줄이 아니라 **사용한** 줄 번호가 되니 `8`이 찍혀요.
4. `__func__`는 `main` 안에서 펼쳐졌으니 `"main"`이에요.

매크로를 이렇게 많이 썼는데, 원본은 마지막에 오히려 "함수를 쓰라"고 해요. 왜일까요?

## 10. 정리 원칙과 static inline 함수

원본은 함수형 매크로를 쓸 때 지킬 원칙을 이렇게 요약해요: **인자에 괄호, 매크로 전체에 괄호, 세미콜론 피하기, 그리고 static inline 함수 선호.** [A p16]

**왜 inline일까요?** 비서의 찾아 바꾸기는 타입도 모르고, 인자를 글자째 여러 번 붙여 넣어요. 6절에서 원한 "호출 비용 없음"만 얻고 이런 위험은 피하고 싶다면, 함수 자체에 `inline`을 붙이면 돼요.

```c
static inline int square(int x) {
    return x * x;
}
```

`inline` 키워드는 C99에서 들어왔어요. [A p16]
- 컴파일러가 함수 본문을 호출한 자리에 복사해 넣어서 **함수 호출 오버헤드가 없어요.**
- 하지만 **힌트일 뿐**이에요. 실제로 인라인할지는 컴파일러가 정해요.
- 매크로와 달리 **타입 검사**를 하고, 인자를 **한 번만** 평가해요.

> 보충: 인자를 한 번만 평가한다는 게 왜 중요한지 예를 들면, `SQ(i++)`는 `((i++) * (i++))`로 펼쳐져 `i`가 두 번 증가하지만, `square(i++)`는 `i++`를 한 번만 계산해서 넘겨요.

## 한눈에 이어 보기

- 전처리기(컴파일 전 편집 비서) → `#` 지시문으로 명령 → `#include`로 문서 끼워 넣기(`<>` 시스템 위치, `""` 현재 디렉터리 먼저)
- `#define` 찾아 바꾸기 → 객체형 매크로(상수·문법 설탕) → 함수형 매크로(인자를 글자째 붙여 넣기)
- 글자째 붙여 넣기 때문에 → 인자 괄호·전체 괄호 필수, 이름 뒤 공백·끝 세미콜론 금지
- 호출 오버헤드 없는 인라인 코드 → `min`, `CUBE`, `F_POW`, `getchar`·`ctype.h` 매크로
- 넣고 빼기 → 조건부 컴파일(디버그 플래그·플랫폼별 코드·헤더 가드) → 미리 정의된 매크로로 위치 정보 출력
- 매크로의 위험(타입 없음, 중복 평가) → static inline 함수 선호
