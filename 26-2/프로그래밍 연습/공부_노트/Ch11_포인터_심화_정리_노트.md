# Ch11 포인터 심화 정리 노트

> 범위: A p2–45 (구간 표지 p15·24·31·37 제외) · 출처 약어: A = chap11. Pointers in Depth.pdf

## 1. 핵심 개념

### 1-1. 다차원 배열과 배열 포인터
- **다차원 배열(multidimensional array)**: 배열의 배열. `int b[2][7]` 2차원, `int c[5][3][2]` 3차원 [A p2]
- **행 우선(row-major) 저장**: 기준 주소부터 0행 → 1행 → 2행 순으로 빈틈없이 연속 저장. `int a[3][5]` = int 15개 연속 [A p2–4]
- **배열 붕괴(array decay)**: 배열 타입의 식은 첫 원소 포인터로 변환. 예외는 `sizeof`, 단항 `&`의 피연산자 [A p3, p13]
- **기준 주소(base address)** `&a[0][0]`: 타입 `int *`. `a`와 주소값은 같지만 타입이 다름. C 표준 용어는 아님(표준 표현: 첫 원소를 가리키는 포인터) [A p3]
- **배열 포인터(pointer to array)** `int (*p)[5]`: int 5개짜리 배열(한 행)을 가리키는 포인터 [A p3, p7]
- `&a`: 2차원 배열 전체를 가리키는 포인터, 타입 `int (*)[3][5]`. 배열에 `&` → 배열 타입 포인터(ANSI C89부터 표준, K&R 이전 컴파일러는 무시) [A p8]

| 식 (`int a[3][5]`) | 실제 타입 | 붕괴 후 타입 | 같은 식 | 가리키는 것 | +1 이동량 |
|---|---|---|---|---|---|
| `&a` | `int (*)[3][5]` | — | — | 배열 전체 | 60바이트(sizeof a) |
| `a` | `int [3][5]` | `int (*)[5]` | `&a[0]` | 0행 | 20바이트(한 행) |
| `*a`, `a[0]` | `int [5]` | `int *` | `&a[0][0]` | 0행 0열 | 4바이트(int 1개) |
| `&a[0][0]` | `int *` | (붕괴 없음) | — | 0행 0열 | 4바이트 |

[A p8–14]

### 1-2. 포인터 배열과 3차원 배열
- **포인터 배열(array of pointers)** `int *parray[3] = {array1, array2, array3};`: 각 원소가 1차원 배열의 첫 주소. `parray[i][j]`로 2차원처럼 사용 [A p16]
- 행 길이가 서로 달라도 됨(들쭉날쭉) → 행 길이를 `len[]` 등에 따로 보관 [A p17]

| 3차원 동적 배열 | 방법 1: `int **images[3]` | 방법 2: `int (*images[3])[WIDTH]` |
|---|---|---|
| 타입 | images `int **[3]`, images[0] `int *[5]`, images[0][i] `int[5]` | images `int (*[3])[5]` (행 포인터 3개짜리 배열) |
| 할당 | `images[img] = (int **)malloc(HEIGHT*sizeof(int *))` 후 행마다 `images[img][i] = (int *)malloc(WIDTH*sizeof(int))` | `images[img] = (int (*)[WIDTH])malloc(sizeof(int)*HEIGHT*WIDTH)` |
| 블록 수 | 18개(포인터 배열 3 + 행 15), 행끼리 떨어져 있음 | 이미지당 연속 블록 1개 |
| 해제 | 역순: `free(images[img][i])` 전부 → `free(images[img])` | `free(images[img])` 한 번 |
| 접근 | `images[img][i][j]` | `images[img][i][j]` |

[A p18–23]

### 1-3. 복잡한 선언
| 선언 | 의미 |
|---|---|
| `char **argv` | char 포인터를 가리키는 포인터 |
| `int (*daytab)[13]` | int 13개 배열을 가리키는 포인터 |
| `int *daytab[13]` | int 포인터 13개짜리 배열 |
| `int array[3][4]` | 타입 `int[3][4]`, 대부분 식에서 `int (*)[4]`로 붕괴 |
| `void *comp()` | void 포인터를 반환하는 함수 |
| `void (*comp)()` | void를 반환하는 함수를 가리키는 포인터 |
| `void (*comp[3])()` | void 반환 함수 포인터 3개짜리 배열 |
| `char (*(*comp[3])(void))[5]` | char 5개 배열의 포인터를 반환하는 함수 포인터 3개짜리 배열 |
| `char (*(*x())[])()` | char 반환 함수 포인터들의 배열(크기 미지정)을 가리키는 포인터를 반환하는 함수 |

[A p26–30]

- typedef 분해: `typedef char CharArray5[5]; typedef CharArray5 *Func(void); Func *comp[3];` [A p28]
- typedef 분해: `typedef char (*CharFuncPtr)(void); typedef CharFuncPtr FuncPtrArray[]; FuncPtrArray *x(void);` [A p30]

### 1-4. 함수 포인터와 정렬
- **퀵정렬(quicksort)**: 분할 정복 정렬, Tony Hoare(1959). 피벗 선택 → 피벗보다 작은 쪽 / 크거나 같은 쪽으로 분할 → 각 쪽 재귀 정렬 [A p32]
- **`qsort`**: `<stdlib.h>`의 표준 함수. 이름만 퀵정렬에서 왔고 알고리즘은 표준이 정하지 않음 [A p32]
- **비교 함수**: 두 원소를 받아 앞이 작으면 음수(-1), 크면 양수(1), 같으면 0 반환. 함수 이름을 그대로 인자로 넘기면 함수 포인터로 전달 [A p34–36]

### 1-5. 문자열과 포인터
| 항목 | `char *pc = "apple";` | `char str[50] = "apple";` |
|---|---|---|
| 메모리 | 포인터만 스택, 문자들은 읽기 전용 영역 | 50바이트 전부 str 소유(스택), 초기화 때 문자 복사 |
| 대입 | `pc = "banana";` 가능(다른 문자열 가리킴) | `strcpy(str, "banana");`로 복사 (`str = "banana";`는 오류) |
| 크기 | `sizeof(pc)` 8바이트(32비트 4바이트) | `sizeof(str)` 50바이트 |
| 수정 | `pc[0] = 't';` UB | `str[0] = 't';` 가능 |
| 입력 | `scanf("%s", pc);` UB | `scanf("%49s", str);` (최대 49자 + `'\0'`) |

[A p38–39]

- **문자열 리터럴(string literal)**: 배열 이름처럼 첫 문자 포인터로 취급. 보통 읽기 전용 메모리, 수정 시 UB [A p40]
- **메모리 배치(32비트 x86 Linux)**, 높은 주소 → 낮은 주소 [A p41]

| 영역 | 내용 |
|---|---|
| 커널 공간 (0xC0000000–0xFFFFFFFF, 1GB) | 사용자 코드 접근 불가. 아래 나머지 3GB가 사용자 프로그램 영역 |
| 스택 ↓ | 지역 변수, 반환 주소 |
| 메모리 매핑 영역 | 공유 라이브러리, mmap |
| 힙 ↑ | malloc / free |
| BSS | 초기화하지 않은 정적 변수 |
| Data | 초기화한 정적 변수 |
| 읽기 전용 데이터 | 문자열 리터럴, const 전역 변수 |
| Text(코드 영역, 0x08048000부터) | 기계어 명령(읽기 전용) |
| 예약 영역(0x00000000) | 매핑 안 됨, NULL 접근 시 오류 |

## 2. 공식
| 공식·형식 | 의미 | 조건·비고 |
|---|---|---|
| 원소 수 $s_1 \times s_2 \times \cdots \times s_k$ | k차원 배열이 차지하는 원소 수 | $s_i$ = i번째 차원 크기 [A p2] |
| `a[i][j]` ≡ `*(*(a + i) + j)` | 2차원 원소 접근의 표준 정의 | 동치: `*(a[i] + j)`, `(*(a + i))[j]`, `*((*(a + i)) + j)`, `*(&a[0][0] + 5*i + j)` [A p5] |
| $\text{addr}(a[i][j]) = \&a[0][0] + (i \times 5 + j) \times \text{sizeof(int)}$ | `int a[3][5]` 원소 주소 | 열 수 5가 있어야 계산 가능 [A p5] |
| `int a[][5]` ⇔ `int a[3][5]` ⇔ `int (*a)[5]` | 2차원 배열 매개변수 | 첫 차원 제외 모두 명시 [A p6] |
| `int b[]` ⇔ `int b[3]` ⇔ `int *b` | 1차원 배열 매개변수 | 함수 매개변수에서만 동치 [A p6] |
| `void qsort(void *base, size_t nmemb, size_t size, int (*compar)(const void *, const void *));` | 시작 주소, 원소 개수, 원소 크기, 비교 함수 | `<stdlib.h>` [A p32] |
| `void quicksort(void *v[], int left, int right, int (*comp)(const void *, const void *));` | 강의 퀵정렬 | 비교 `comp(v[i], v[left]) < 0`, 교환 `swap(void *v[], int i, int j)` [A p33] |
| `fgets(buffer, SIZE, stdin);` / `scanf("%79s", buffer);` | 길이 제한 입력 | `%` 뒤 숫자 = SIZE − 1 [A p42] |
| `ssize_t getline(char **lineptr, size_t *n, FILE *stream);` | 한 줄 전체 입력 | POSIX, `ssize_t` = 부호 있는 크기 타입 [A p44] |
| `while ((ch = getchar()) != '\n' && ch != EOF);` | 입력 버퍼 남은 문자 버리기 | 표준 flush 함수 없음 [A p42] |

## 3. 원리·결론
- 다차원 배열 매개변수의 첫 차원 크기는 강제되지 않음. 컴파일러는 실제 행 수를 확인하지 않음 [A p6]
- 열 크기를 명시해야 하는 이유: 컴파일러의 메모리 매핑(행 하나의 길이) 계산 [A p6]
- `a`, `&a`, `a[0]`, `&a[0][0]`, `*a`는 주소값이 모두 같고 타입(=+1 이동량, sizeof)만 다름 [A p7–12]
- `sizeof a[0]` = 20(행 전체), `sizeof &a[0][0]` = 8(포인터) [A p11]
- 선언 해석: 이름에서 시작, `[]`·`()`(후위, 1순위)가 `*`(단항, 2순위)보다 먼저 결합. 괄호로 순서 변경 [A p27, p29]
- 함수는 배열을 반환할 수 없음 → 배열의 포인터를 반환 [A p28]
- 크기 미지정 배열 `[]`을 가리키는 포인터는 허용 [A p30]
- 강의 `quicksort`는 원소 자체(`v[i]`)를 비교 함수에 넘김, 표준 `qsort`는 원소를 가리키는 포인터를 넘김 [A p34]
- 메모리 해제는 할당의 역순 [A p20]
- `scanf("%s")`는 기본적으로 입력 길이를 검사하지 않음 → 버퍼 오버플로(buffer overflow) [A p42]
- `scanf("%79s")`는 공백으로 구분된 토큰 하나만 읽음. 이전 내용이 뒤에 남아도 printf는 첫 `'\0'`에서 멈춤 [A p43]
- getline 동작: `buffer`가 NULL이면 malloc 후 크기를 `size`에 저장 / `'\n'` 포함 한 줄 읽기(EOF 제외) / 줄이 길면 재할당 후 `size` 갱신 / 반환값 = 읽은 문자 수(개행 포함, `'\0'` 제외), EOF·오류 시 −1 [A p44]
- getline은 표준 C가 아닌 POSIX 함수, Windows MSVC에는 없음 [A p44]

**연산자 우선순위(요약)** [A p25, p27]

| 순위 | 연산자 | 결합 방향 |
|---|---|---|
| 1 | 후위 `++ --`, 함수 호출 `()`, 첨자 `[]`, `.`, `->`, 복합 리터럴 `(type){...}` | 좌 → 우 |
| 2 | 전위 `++ --`, 단항 `+ -`, `! ~`, 캐스트 `(type)`, 역참조 `*`, 주소 `&`, `sizeof`, `_Alignof` | 우 → 좌 |
| 3–12 | `* / %` → `+ -` → `<< >>` → `< <= > >=` → `== !=` → `&` → `^` → `\|` → `&&` → `\|\|` | 좌 → 우 |
| 13 | `?:` | 우 → 좌 |
| 14 | `=`, `+= -= *= /= %= <<= >>= &= ^= \|=` | 우 → 좌 |
| 15 | `,` | 좌 → 우 |

## 4. 문제 유형별 접근
- 포인터 식의 타입·이동량 묻기: 실제 타입 판정 → `sizeof`/`&` 피연산자인지 확인 → 아니면 붕괴 타입 → 가리키는 대상 크기 = +1 이동 바이트
- `a[i][j]` 주소 계산: (i × 열 수 + j) × 원소 크기를 기준 주소에 더함
- 2차원 배열을 받는 함수 작성: 매개변수 `int a[][열]` 또는 `int (*a)[열]`, 행 수는 따로 인자로
- 길이가 다른 행 다루기: 포인터 배열 + 행 길이 배열, 루프 조건 `j < len[i]`
- 3차원 동적 할당: 바깥 → 안쪽 순서로 malloc, 안쪽 → 바깥 순서로 free
- 복잡한 선언 읽기: 이름 → 오른쪽 `[]`/`()` → 왼쪽 `*` → 괄호 밖으로 → 맨 왼쪽 기본 타입. 함수가 배열을 반환하는 모양이면 오류
- 정렬 기준 바꾸기: 비교 함수 작성(`const void *` → 실제 타입 포인터로 캐스트 → 음수/0/양수 반환) → 함수 이름을 인자로 전달
- 문자열 수정·입력 판단: 포인터(리터럴 가리킴)인지 배열인지 먼저 구분

## 5. 실수 포인트
- `&a + 1`은 한 행이 아니라 배열 **전체**를 건너뜀(`int a[3][5]`에서 60바이트)
- `a`와 `&a[0][0]`은 주소가 같아도 타입이 다름 → +1 결과가 다름
- 2차원 배열 매개변수에서 열 크기 생략 불가(`int a[][]` 안 됨)
- `int (*p)[5]`(배열 포인터)와 `int *p[5]`(포인터 배열) 혼동 주의
- 함수가 배열을 반환하는 선언(`char f()[10]` 등)은 컴파일 오류
- 표준 `qsort`용 비교 함수는 원소의 **포인터**를 받음: 문자열 배열이면 `*(const char **)s1`, 강의 `quicksort`용이면 `(const char *)s1`
- `%p`에는 `(void *)` 캐스트, 포인터를 `%d`로 출력하면 UB
- 리터럴을 가리키는 `char *`로 수정·`scanf` 입력 금지(UB)
- 배열 이름에는 대입 불가(`str = "banana"` 오류) → `strcpy` 사용
- `scanf("%s")` 길이 미지정은 오버플로 위험, 폭은 버퍼 크기 − 1
- fgets/`%79s` 뒤에 남은 문자는 다음 입력이 읽음 → getchar 루프로 비우기
- getline이 −1을 반환해도 `free(buffer)` 호출(이미 할당했을 수 있음)
