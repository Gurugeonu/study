# Ch10 구조체와 리스트 처리 설명

> 범위: A p2–34 · 출처 약어: A = chap10. Structures and List Processing.pdf

이 단원은 하나의 이야기로 따라가요. 지우가 친구들을 위해 **보물찾기 쪽지 놀이**를 준비해요. 쪽지마다 글자가 하나씩 적혀 있고, 쪽지 아래쪽에는 "다음 쪽지는 어디에 있어요"라는 위치가 적혀 있어요. 마지막 쪽지에는 "끝"이라고 적혀 있고요. 이 쪽지 놀이 하나로 단원 전체를 설명할 거예요.

> 보충: 보물찾기 쪽지 비유는 원본에 없는 이해용 비유예요.

## 1. 자기 참조 구조체: 다음 쪽지의 위치를 적는 칸

**왜 필요할까요?** 배열은 칸 수를 미리 정해야 하고, 칸들이 메모리에 나란히 붙어 있어야 해요. 그런데 지우는 친구가 몇 명 올지 몰라서 쪽지를 몇 장 만들지 정할 수 없어요. 쪽지가 흩어져 있어도 서로 위치만 알려 주면 된다면 훨씬 편하겠죠.

**직관:** 쪽지 한 장 = 내용 칸 + "다음 쪽지 위치" 칸. 다음 쪽지도 똑같이 생긴 쪽지라서, 쪽지가 **자기와 같은 모양의 쪽지**를 가리키는 셈이에요.

**정의:** 자기 참조 구조체(self-referential structure)는 같은 구조체 타입을 가리키는 포인터 멤버를 하나 이상 가진 구조체예요. [A p2]

```c
struct node {
    int data;           // 쪽지 내용
    struct node *next;  // 다음 노드를 가리키는 포인터 = 링크(link)
};
```

`typedef struct node { ... } Node;`처럼 별칭을 붙이면 `Node a;`로 짧게 선언할 수 있어요. 구조체 하나하나를 노드(node)라고 불러요.

**장점** [A p3]
- 연결 리스트(linked list), 트리(tree), 그래프(graph) 같은 동적 자료구조를 만들 수 있어요. 슬라이드 그림에는 일렬로 이어진 리스트, 31을 뿌리로 가지가 갈라지는 트리, K·M·T가 화살표로 이어진 그래프가 나와요.
- 노드를 개수 제한 없이 이어 붙일 수 있어서 유연하고 늘리기 쉬워요.
- 각 노드가 포인터로 다음 노드와 연결되어, 따라갈 수 있는 사슬이 돼요.

그런데 이번엔 쪽지 세 장을 실제로 이어 보면 어떻게 될까요?

## 2. 쪽지 세 장을 손으로 잇기

지우는 먼저 쪽지 `a`, `b`, `c`를 변수로 만들고 내용을 1, 2, 3으로 적어요. 처음에는 셋 다 "끝"(`NULL`)을 적어 둬요. [A p4]

```c
a.next = b.next = c.next = NULL;   // 아직 아무 데도 연결 안 됨
a.next = &b;                       // a → b
b.next = &c;                       // b → c
```

이제 `a`만 알면 나머지를 찾아갈 수 있어요. [A p5]
- `a.next->data`: `a`의 다음 쪽지(`b`)의 내용 → `2`
- `a.next->next->data`: `a` → `b` → `c`의 내용 → `3`

**읽는 법:** `->`를 왼쪽부터 하나씩 따라가며 "지금 어느 쪽지에 와 있는지"를 세면 돼요. 그래서 출력은 `2`, `3`이에요.

그런데 쪽지를 매번 변수 이름으로 만들면 개수가 고정돼요. 첫 쪽지 위치만 들고 다니는 방법은 없을까요?

## 3. 선형 연결 리스트: head 메모와 "끝" 표시

**정의:** 선형 연결 리스트(linear linked list)는 노드들을 일직선으로, 즉 원을 이루지 않게 나열한 거예요. [A p6]
- `head` 포인터는 첫 원소의 주소를 가리켜요. 지우 주머니에 든 "첫 쪽지는 여기" 메모예요.
- 각 원소는 다음 원소와 연결돼요.
- 마지막 원소의 링크는 `NULL`이라서, 뒤에 더 이상 원소가 없다는 뜻이에요.

슬라이드 그림에는 `head → n → e → w → NULL`인 단일 연결 리스트와, 앞뒤 화살표가 모두 있는 `12 ⇄ 99 ⇄ 37`(양 끝 `NULL`)이 함께 나와요. 즉 "선형"은 **원형이 아니라는 뜻**이고, 양방향 리스트도 끝이 막혀 있으면 선형이에요.

이제 이 리스트를 실제 프로그램에서 쓰려면 이름표부터 정리해야겠죠?

## 4. 쪽지 규격 정하기와 malloc으로 쪽지 만들기

**타입 정리 (`list.h`)** [A p7]

```c
typedef char DATA;              // 쪽지 내용은 문자 하나
struct node { DATA d; struct node *next; };
typedef struct node ELEMENT;    // 쪽지 한 장
typedef ELEMENT *LINK;          // 쪽지를 가리키는 포인터
```

`DATA`를 바꾸면 내용 타입을 한 번에 바꿀 수 있어요. `LINK head;`는 `ELEMENT *head;`와 같아요.

**쪽지를 필요할 때마다 만들기** [A p8–10]

변수 대신 `malloc`으로 쪽지를 한 장씩 새로 받아요. "new"를 저장하는 과정이에요.

```c
head = malloc(sizeof(ELEMENT));
if (head == NULL) exit(EXIT_FAILURE);   // 할당 실패
head->d = 'n';  head->next = NULL;

head->next = malloc(sizeof(ELEMENT));    // 두 번째 쪽지
head->next->d = 'e';  head->next->next = NULL;

head->next->next = malloc(sizeof(ELEMENT));  // 세 번째 쪽지
head->next->next->d = 'w';  head->next->next->next = NULL;
```

각 단계에서 "새 쪽지를 받는다 → 받았는지 확인한다 → 내용을 적는다 → 일단 끝 표시를 한다"를 반복해요. 두·세 번째 할당 뒤에도 똑같이 `NULL` 검사를 해요. 메모리가 부족하면 `malloc`이 `NULL`을 돌려주기 때문이에요.

**왜 `(ELEMENT *)` 캐스트를 안 붙일까요?** [A p8]
- `malloc`은 `void *`를 돌려줘요.
- C에서는 `void *`가 어떤 객체 포인터 타입으로든 자동으로 바뀌어요. 그래서 `head = malloc(sizeof(ELEMENT));`로 충분해요.
- C++은 `void *`를 암시적으로 바꿔 주지 않아서 캐스트가 필요해요.

그런데 `head->next->next->next`처럼 화살표가 계속 길어지면 쪽지가 100장일 때는 어떻게 할까요? 반복이나 재귀로 처리해야 해요.

## 6. 리스트 만들기: 반복과 재귀

### 6-1. 반복: tail이 꼬리를 따라가요

**왜:** 문자열 `"AB"`를 받아 쪽지 사슬로 바꾸고 싶어요. 매번 맨 앞에서부터 끝까지 걸어가면 느리니까, **마지막 쪽지 위치를 따로 기억하는 `tail`**을 둬요.

**핵심 줄 (`s_to_l`)** [A p12]

```c
LINK head = NULL, tail;
if (s[0] != '\0') {
    head = malloc(sizeof(ELEMENT));   // + NULL 검사
    head->d = s[0];
    tail = head;
    for (i = 1; s[i] != '\0'; ++i) {
        tail->next = malloc(sizeof(ELEMENT));  // + NULL 검사
        tail = tail->next;
        tail->d = s[i];
    }
    tail->next = NULL;    /* end of list */
}
return head;
```

**`s_to_l("AB")` 따라가기** [A p13]
1. 첫 쪽지를 받아 `A`를 적고, `head`와 `tail`이 둘 다 이 쪽지를 가리켜요. 이때 링크 칸은 아직 `?`(정해지지 않은 값)이에요.
2. `tail->next`에 새 쪽지를 붙여요. 새 쪽지는 내용도 링크도 `?`예요.
3. `tail = tail->next`로 꼬리를 새 쪽지로 옮기고 `B`를 적어요. `head`는 여전히 `A`에 있어요.
4. 루프가 끝나면 `tail->next = NULL`로 끝 표시를 해요. 이 줄을 빠뜨리면 마지막 링크가 `?`로 남아 엉뚱한 곳을 가리켜요.

빈 문자열이면 `if`를 건너뛰어 `head`는 `NULL`, 즉 빈 리스트를 돌려줘요.

### 6-2. 재귀: "첫 글자만 내가, 나머지는 너가"

**직관:** 지우는 첫 쪽지만 직접 만들고, "나머지 글자로 만든 사슬의 첫 쪽지 위치"를 링크 칸에 적어요. 나머지는 똑같은 방법으로 친구가 만들어 줘요.

**핵심 줄 (`string_to_list`)** [A p14]

```c
if (s[0] == '\0') return NULL;            // 기저: 빈 문자열
head = malloc(sizeof(ELEMENT));           // + NULL 검사
head->d = s[0];
head->next = string_to_list(s + 1);       // 나머지 문자열로 재귀
return head;
```

**왜 이렇게 하나요?**
- `s + 1`은 두 번째 글자부터 시작하는 문자열이라 문제가 한 글자씩 작아져요.
- 결국 빈 문자열에 닿으면 `NULL`이 돌아오고, 그게 마지막 쪽지의 링크가 돼요. 그래서 `tail->next = NULL` 같은 줄이 따로 필요 없어요.

만든 리스트에 쪽지가 몇 장인지 세려면 어떻게 할까요?

## 7. 개수 세기와 재귀 처리의 틀

**반복 (`count_it`)** [A p15]

```c
for ( ; head != NULL; head = head->next)
    ++cnt;
```

`head`를 한 칸씩 옮기며 `NULL`을 만날 때까지 세요. `head`는 매개변수 복사본이라 함수 밖의 `head`는 바뀌지 않아요.

**재귀 (`count`)** [A p16]

```c
if (head == NULL) return 0;
else return 1 + count(head->next);
```

"내 쪽지 1장 + 나머지 사슬의 장수"예요. 빈 리스트는 0장이고요.

**리스트 재귀의 일반 틀** [A p18]

```c
if (head == NULL) { /* 기저: 빈 리스트 */ }
else { /* head 처리 */  generic_recursion(head->next); }
```

리스트 재귀 함수는 거의 다 이 모양이에요. 빈 리스트가 기저이고, `head->next`가 "한 장 줄어든 문제"예요. 앞의 `string_to_list`, `count`와 다음의 `concatenate`, `delete_list` 모두 이 틀에 맞춰져 있어요.

이번엔 지우가 친구가 만든 쪽지 사슬을 자기 사슬 뒤에 이어 붙이고 싶다면 어떻게 될까요?

## 8. 두 리스트 이어 붙이기

**목표:** 리스트 `a`의 마지막 노드 뒤에 리스트 `b`의 모든 노드가 오게 해요. 둘 중 어느 쪽이 비어 있어도 돼요. [A p17]

```c
LINK concatenate(LINK a, LINK b) {
    if (a == NULL) return b;              // 기저: 첫 리스트가 비었음
    a->next = concatenate(a->next, b);    // 재귀
    return a;
}
```

**단계별로 왜 이렇게 하나요?**
1. `a`가 비어 있으면 이어 붙인 결과는 그냥 `b`예요.
2. 그렇지 않으면 "내 뒤쪽(`a->next`)과 `b`를 이은 결과"를 내 링크 칸에 다시 적어요.
3. 이걸 반복하면 결국 `a`의 마지막 노드에서 `a->next`가 `NULL`이 되고, 그 자리에 `b`가 들어가요.
4. 앞쪽 노드들은 링크가 원래 값 그대로 다시 적히니 변하지 않아요. 맨 앞 `a`를 돌려주면 전체 사슬의 시작이 돼요.

이번엔 사슬 중간에 쪽지를 하나 끼워 넣으면 어떻게 될까요?

## 9. 삽입: 왜 리스트가 배열보다 빠를까

**배열과 비교** [A p19]
- 배열 `1 2 3 4`의 인덱스 2에 `X`를 넣으려면 `3`, `4`를 한 칸씩 오른쪽으로 밀어야 해요. 원소가 많을수록 밀 게 많아져서 평균 $O(n)$이에요($n$ = 배열 원소 수).
- 리스트 `1 → 2 → 3`에서 `2` 뒤에 `5`를 넣을 때는 쪽지 두 장의 링크 칸만 고치면 돼요. 넣을 위치가 이미 정해져 있다면 원소 수와 상관없이 $O(1)$, 상수 시간이에요.

**연속한 두 노드 사이에 넣기 (`insert`)** [A p20]

```c
assert(p1->next == p2);   // p1 바로 뒤가 p2인지 확인
p1->next = q;             // A → B
q->next = p2;             // B → C
```

- `p1`(A)와 `p2`(C) 사이에 `q`(B, 처음엔 링크 `NULL`)를 넣어요.
- `assert`는 "정말 붙어 있는 두 노드인가?"를 확인해요. 아니면 프로그램이 멈춰서 실수를 바로 알려 줘요.
- 이 함수는 `p2`를 따로 받으니 두 줄의 순서를 바꿔도 돼요.

> 보충: `p2` 없이 `p1`만 받는 삽입이라면 `q->next = p1->next;`를 **먼저** 해야 해요. `p1->next`를 먼저 덮으면 C의 위치를 잃어버려요.

끼워 넣는 건 쉬웠어요. 그렇다면 쪽지 한 장을 빼는 것도 쉬울까요?

## 10. 삭제: 버린 쪽지를 정말 버렸나요

`delete(p)`는 `p`가 가리키는 노드 **바로 다음** 노드를 지워요. [A p21–22]

### 10-1. 잘못된 버전

```c
p->next = p->next->next;   /* B가 쓰레기(garbage)가 됨 */
```

A의 링크가 C를 가리키니 사슬에서는 B가 빠졌어요. 하지만 B 쪽지는 여전히 메모리 어딘가에 남아 있고, 이제 아무도 B의 위치를 몰라요. 위치를 모르니 `free`로 돌려줄 수도 없어요.

| 개념 | 뜻 |
|---|---|
| 도달 불가 노드(unreachable node) | 가리키는 포인터가 하나도 없어 영영 해제할 수 없는 노드 → 메모리 누수(memory leak) |
| 매달린 포인터(dangling pointer) | 이미 해제한 메모리의 주소를 계속 들고 있는 포인터. 예: `free(temp)` 뒤의 `temp` |

둘은 반대 상황이에요. 도달 불가 노드는 "메모리는 있는데 포인터가 없음", 매달린 포인터는 "포인터는 있는데 메모리가 없음"이에요.

### 10-2. 올바른 버전

```c
if (p != NULL && p->next != NULL) {
    LINK temp = p->next;        // 지울 쪽지 위치를 메모해 두고
    p->next = p->next->next;    // 사슬에서 건너뛴 다음
    free(temp);                 // 메모 덕분에 돌려줄 수 있어요
}
```

- `if` 조건: `p`가 없거나 `p` 뒤에 지울 노드가 없으면 `p->next->next`를 읽다 터지니 미리 막아요.
- `temp`가 B를 붙잡고 있으니 사슬에서 뺀 뒤에도 `free`할 수 있어요.
- `free(temp)` 뒤의 `temp`는 매달린 포인터라서 다시 쓰면 안 돼요.

쪽지 한 장이 아니라 사슬 전체를 치우려면 어떻게 할까요?

## 11. 리스트 전체 삭제

**재귀 버전: 뒤에서부터 치우기** [A p23]

```c
if (head != NULL) {
    delete_list(head->next);   // 뒤쪽을 먼저 다 치우고
    free(head);                // 마지막에 나를 치워요
}
```

해제를 재귀 호출 **뒤**에 하니 후위(post-order) 순회예요. 순서를 바꿔 `free(head)`를 먼저 하면 그 뒤 `head->next`는 이미 돌려준 메모리를 읽는 셈이라 안 돼요.

**반복 버전: 다음 위치를 먼저 메모하기** [A p24]

```c
while (current != NULL) {
    next = current->next;   // 다음 쪽지 위치를 먼저 메모
    free(current);          // 지금 쪽지 치우기
    current = next;         // 메모한 곳으로 이동
}
```

`free(current)` 뒤에는 `current->next`를 읽을 수 없어서 `next`를 먼저 저장해요. 삭제에서 `temp`를 둔 것과 같은 이유예요.

이제 지우는 쪽지를 사슬이 아니라 **위로 쌓아** 쓰고 싶어졌어요. 쌓는 쪽지 더미는 어떤 규칙을 따를까요?

## 12. 스택: 맨 위 쪽지만 만질 수 있어요

**정의:** 스택(stack)은 LIFO(Last In, First Out) 모음이에요. 마지막에 넣은(push) 원소가 가장 먼저 나와요(pop). [A p25]

**연산**
- `push(data)`: 맨 위에 놓기
- `pop()`: 맨 위 원소를 빼서 돌려주기
- `top()`: 맨 위 원소를 빼지 않고 돌려주기
- `isEmpty()`: 비었는지 확인

**예:** `push(1)`, `push(2)`, `push(3)` 하면 더미는 아래부터 1, 2, 3이에요. `pop()`하면 `3`이 나와요.

**어디에 쓰나요?**
- 호출 스택(call stack)
- 실행 취소(undo) 기록: 가장 최근 작업부터 되돌려요.
- 구문 분석: 여는 괄호 `(`, `[`, `{`를 만날 때마다 push하고, 닫는 괄호를 만날 때마다 pop해서 짝이 맞는지 확인해요.

### 12-1. 호출 스택과 메모리 지도 [A p26]

함수 호출도 쪽지 더미처럼 쌓여요. 프로그램이 시작하면 `main()`의 스택 프레임이 생겨요. `main`이 `a()`를 부르면 `a`의 프레임이 그 위에, `a`가 `b()`를 부르면 `b`의 프레임이 또 위에 쌓여요. `b`가 반환하면 `b` 프레임이 빠지고, 다시 `a`가 `c()`를 부르면 그 자리에 `c` 프레임이 들어와요. `c`, `a` 순서로 반환하면 `main`만 남아요. 늦게 불린 함수가 먼저 끝나니 LIFO 그대로예요. 그림에서 스택은 높은 주소에서 낮은 주소 쪽으로 자라요.

32비트 x86에서 돌아가는 Linux의 메모리 배치는 위(높은 주소)부터 이래요.
- `0xC0000000`~`0xFFFFFFFF`, 1 GB: OS 커널 공간. 사용자 코드는 접근할 수 없어요.
- 스택 (아래로 자람): 지역 변수, 반환 주소
- 사용하지 않는 빈 공간
- 힙 (위로 자람): `malloc` / `free`로 받는 곳. 지금까지 만든 쪽지들이 전부 여기 있어요.
- BSS: 초기화하지 않은 static 변수
- Data: 초기화한 static 변수
- Text(코드 영역, `0x08048000`부터): 기계어 명령, 읽기 전용
- 맨 아래 `0x00000000`부터: 예약 영역(매핑 안 됨). `NULL` 포인터에 접근하면 여기서 오류가 나요.

커널 1 GB를 뺀 나머지 3 GB가 사용자 영역이에요. 그림은 스택과 힙이 빈 공간을 사이에 두고 마주 보며 자라는 모습이에요.

이제 쪽지 더미를 연결 리스트로 직접 만들어 볼까요?

## 13. 연결 리스트로 스택 만들기

**구조 (`stack.h`)** [A p27]

```c
#define EMPTY 0
#define FULL  10000
typedef char data;
struct elem  { data d; struct elem *next; };   // 쪽지 한 장
struct stack { int cnt; elem *top; };          // 장수 + 맨 위 쪽지 위치
```

`top`이 리스트의 `head` 역할을 해요. 맨 위 쪽지에서 시작해 아래로 내려가다 마지막 쪽지 링크가 `NULL`이에요. 함수는 `initialize`, `push`, `pop`, `top`, `isEmpty`, `isFull`이고, 스택을 바꾸지 않는 `top`, `isEmpty`, `isFull`은 `const stack *`를 받아요.

**`initialize`** [A p28]: `stk->cnt = 0; stk->top = NULL;` 쪽지 0장, 맨 위 없음.

**`push`** [A p28]

```c
p = malloc(sizeof(elem));          // + NULL 검사
p->d = d;
p->next = stk->top;   // 새 쪽지가 지금 맨 위 쪽지를 가리키고
stk->top = p;         // 새 쪽지가 맨 위가 돼요
stk->cnt++;
```

리스트의 **맨 앞에 삽입**하는 것과 같아요. 순서가 중요해요. `stk->top = p`를 먼저 하면 원래 맨 위 쪽지 위치를 잃어버려요.

**`pop`** [A p29]

```c
if (isEmpty(stk)) exit(EXIT_FAILURE);   // 스택 언더플로(underflow)
d = stk->top->d;           // 내용 꺼내 두기
p = stk->top;              // 버릴 쪽지 메모
stk->top = stk->top->next; // 맨 위를 한 칸 아래로
stk->cnt--;
free(p);
return d;
```

10장의 올바른 삭제와 같은 모양이에요. `p`로 붙잡아 두고, 건너뛰고, `free`해요. 내용 `d`를 `free` 전에 꺼내 두는 것도 같은 이유예요.

**`top`, `isEmpty`, `isFull`** [A p30]

```c
if (isEmpty(stk)) exit(EXIT_FAILURE);   // top도 빈 스택이면 언더플로
return (stk->top->d);
return ((bool) (stk->cnt == EMPTY));    // isEmpty
return ((bool) (stk->cnt == FULL));     // isFull
```

- 빈 스택은 `cnt`가 0이고 `top`이 `NULL`이에요. 이때 `isEmpty`가 true예요.
- 쪽지가 `FULL`(10000)장이면 `isFull`이 true예요.
- `push` 안에서는 `isFull`을 검사하지 않아요. 그래서 부르는 쪽에서 `if (!isFull(stk)) push(d, stk);`처럼 확인해야 해요.

그런데 `isEmpty`의 반환형 `bool`은 C에 원래 있던 걸까요?

## 14. C의 불리언 타입

**왜:** 예전 C에는 참·거짓 타입이 없어서 `1`과 `0`으로 대신했어요. 그러면 `int`가 "개수"인지 "참·거짓"인지 코드만 보고 알기 어려워요.

**정의** [A p30–31]
- `_Bool`은 C99에서 생긴 키워드로, `0`(거짓)과 `1`(참) 두 값만 담는 타입이에요.
- `bool`은 `_Bool`의 매크로예요.
- C99–C17에서는 `<stdbool.h>`를 포함해야 `bool`, `true`, `false`를 쓸 수 있어요. 이 헤더 안에서 `bool`은 `_Bool`, `true`는 `1`, `false`는 `0`, `__bool_true_false_are_defined`는 `1`로 정의돼요.
- C23부터는 `bool`, `true`, `false`가 키워드라서 헤더가 필요 없어요. `stack.h`에 `#include <stdbool.h>  /* not needed in C23 */`라고 적힌 이유예요.
- `==` 연산의 결과는 `int`(0 또는 1)예요. `isEmpty`의 `(bool)` 캐스트는 타입을 분명히 보여 주려고 붙인 거예요.

**장점:** `1`·`0` 대신 `true`·`false`를 쓰니 코드가 명확하고, 논리식의 의도가 잘 드러나요.

이제 완성한 쪽지 더미로 무엇을 할 수 있을까요?

## 15. 스택으로 문자열 뒤집기 [A p32]

**문제:** `"My name is Joanna Kelly!"`의 글자를 하나씩 스택에 넣었다가 모두 빼면 무엇이 출력될까요?

```c
initialize(&s);
for (i = 0; str[i] != '\0'; ++i)
    if (!isFull(&s)) push(str[i], &s);
while (!isEmpty(&s))
    putchar(pop(&s));
```

**풀이**
1. `initialize`로 빈 더미를 만들어요.
2. `M`, `y`, ` `, `n`, … `!` 순서로 push해요. `isFull` 검사는 부르는 쪽에서 해요(13장).
3. 맨 위에는 마지막 글자 `!`가 있어요.
4. 비어 있지 않은 동안 pop해서 출력하면 `!`, `y`, `l`, `l`, `e`, `K`, … 순서로 나와요.

**출력**
```
 In the string: My name is Joanna Kelly!
From the stack: !ylleK annaoJ si eman yM
```

넣은 순서의 정반대로 나오니 LIFO를 확인할 수 있어요.

마지막으로, 쪽지의 링크 칸을 다르게 만들면 어떤 사슬이 될까요?

## 16. 연결 리스트의 변형 [A p33]

- **단일 연결 리스트(singly linked list):** `64 → 3 → 29 → NULL`. 쪽지마다 "다음" 칸 하나만 있어요. 지금까지 만든 모든 리스트예요.
- **양방향 연결 리스트(doubly linked list):** `NULL ← 18 ⇄ 75 ⇄ 41 → NULL`. 쪽지마다 "이전"과 "다음" 칸이 둘 다 있어서 뒤로도 갈 수 있어요. 양 끝은 `NULL`이에요.
- **원형 연결 리스트(circular linked list):** `56 → 9 → 83 → 56 …`. 마지막 쪽지가 "끝" 대신 첫 쪽지를 가리켜서 고리가 돼요. `NULL`이 없으니 선형 리스트가 아니에요.

이 단원에서 배운 것은 자기 참조 구조체, 선형·단일 연결 리스트, 리스트 처리, 스택, C의 불리언 타입, 연결 리스트 변형이에요. [A p34]

## 한눈에 이어 보기

- 자기 참조 구조체(다음 쪽지 위치 칸) → 노드를 `->`로 잇기 → `head`와 `NULL`로 끝나는 선형 연결 리스트
- `malloc`으로 노드 생성 → 반복(`tail`)·재귀(`s + 1`)로 리스트 생성 → 재귀 틀(빈 리스트 기저, `head->next`)로 개수 세기·이어 붙이기
- 링크만 고치는 삽입 $O(1)$ (배열은 $O(n)$) → `temp`로 붙잡고 `free`하는 삭제(누수·매달린 포인터 주의) → 전체 삭제
- 맨 앞 삽입·삭제만 하는 리스트 = 스택(LIFO) → 호출 스택·메모리 배치 → `bool`을 돌려주는 `isEmpty`/`isFull` → 문자열 뒤집기
- 링크 칸을 바꾸면 단일 → 양방향 → 원형 리스트
