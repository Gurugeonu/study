# Ch11 포인터 심화 설명

> 범위: A p2–45 · 출처 약어: A = chap11. Pointers in Depth.pdf

이 단원은 **아파트 단지** 하나를 무대로 진행해요. 새로 온 관리인 도담이가 단지의 주소 체계를 익히고, 주민 줄을 세우고, 게시판과 우편함을 관리하는 이야기예요. 메모리는 이 단지의 땅이고, 포인터는 "어느 집으로 가라"고 적힌 **주소 쪽지**예요.

## 1. 다차원 배열: 3층짜리 아파트 한 동

### 왜 필요할까요?
도담이가 맡은 첫 건물은 3층, 층마다 5집이 있는 아파트예요. 집집마다 변수를 하나씩 만들면 15개 이름을 외워야 하죠. 그래서 C는 **배열의 배열**, 곧 다차원 배열(multidimensional array)을 허용해요. 대괄호를 두 쌍 쓰면 2차원, 세 쌍 쓰면 3차원이에요 [A p2].

```c
int a[100];      // 1차원
int b[2][7];     // 2차원
int c[5][3][2];  // 3차원
```

k차원 배열은 원소 $s_1 \times s_2 \times \cdots \times s_k$개만큼 자리를 잡아요($s_i$는 i번째 차원의 크기). `int a[3][5]`면 $3 \times 5 = 15$칸이에요.

### 실제로는 한 줄로 서 있어요
그림으로는 3층 × 5집 표처럼 보이지만, 메모리는 사실 **긴 복도 하나**예요. 0층 5집이 먼저 늘어서고, 바로 이어서 1층 5집, 그다음 2층 5집이 빈틈없이 붙어요. 이것을 행 우선(row-major) 저장이라고 해요 [A p2–4].

```
a[0][0] … a[0][4] | a[1][0] … a[1][4] | a[2][0] … a[2][4]
   a[0] (0행)          a[1] (1행)          a[2] (2행)
```

이 복도의 맨 앞 칸 주소 `&a[0][0]`을 흔히 기준 주소(base address)라고 불러요. 다만 이 말은 C 표준 용어가 아니고, 표준은 "배열의 첫 원소를 가리키는 포인터"라고 표현해요 [A p3].

그런데 도담이가 "a동!"이라고 부르면 쪽지에는 정확히 어디가 적힐까요?

## 2. 배열 붕괴와 포인터의 "걸음 크기"

### 이름을 부르면 첫 원소 주소가 돼요
배열 이름은 식 안에서 **첫 원소를 가리키는 포인터**로 바뀌어요. 이것을 배열 붕괴(array decay)라고 해요. 예외는 두 가지, `sizeof`의 피연산자일 때와 단항 `&`의 피연산자일 때예요 [A p3, p13].

`int a[3][5]`에서 a의 원소는 int가 아니라 **int 5개짜리 배열(한 층)** 이에요. 그래서 `a`는 `&a[0]`, 곧 "0층 전체"를 가리키는 포인터로 바뀌고, 타입은 `int (*)[5]`예요. 읽으면 "int 5개짜리 배열을 가리키는 포인터"죠 [A p3, p8].

### 직관: 쪽지마다 걸음 크기가 정해져 있어요
같은 복도 첫 칸을 가리키는 쪽지라도, 쪽지 종류에 따라 "한 걸음(+1)"의 크기가 달라요.
- `int *` 쪽지는 한 집씩 걸어요(4바이트).
- `int (*)[5]` 쪽지는 엘리베이터처럼 한 층씩 움직여요(20바이트).
- `int (*)[3][5]` 쪽지는 건물 하나를 통째로 건너뛰어요(60바이트).

이 비유를 이 장 끝까지 계속 써요.

### 원본 실험으로 확인해요
```c
int (*p1)[5] = &a[0];   // p1=…cf0, p1+1=…d04
int *p2 = &a[0][0];     // p2=…cf0, p2+1=…cf4
```
출발 주소는 같지만 `p1+1`은 0x14 = 20바이트(한 행), `p2+1`은 4바이트(int 하나) 움직였어요 [A p7].

### `&a`: 건물 전체를 가리키는 쪽지
배열에 `&`를 붙이면 붕괴가 일어나지 않아요. 그래서 `&a`는 첫 원소가 아니라 **배열 전체**를 가리키고, 타입은 `int (*)[3][5]`예요. `&a + 1`은 배열 바로 뒤, 곧 `sizeof a` 바이트만큼 떨어진 곳을 가리켜요 [A p8]. 이 규칙은 ANSI C89부터 표준이고, 그 전(K&R 시절) 컴파일러는 배열에 붙은 `&`를 무시했어요.

원본 출력 [A p9]:
```
a:    0x7ffc7fdb6d80
&a:   0x7ffc7fdb6d80
a+1:  0x7ffc7fdb6d94   // +0x14 = 20바이트: 한 층
&a+1: 0x7ffc7fdb6dbc   // +0x3c = 60바이트: 건물 전체
```
`a`와 `&a`는 주소값이 같아도, 걸음 크기가 다르니 +1 결과가 달라요.

주소를 출력할 때는 `%p`를 쓰고 인자를 `(void *)`로 바꿔 줘요. `printf`가 `%p`에 `void *`를 기대하기 때문이에요. 포인터를 `%d`로 찍으면 정의되지 않은 동작(UB, undefined behavior)이에요 [A p9, p10].

### `*a`와 `a[0]`은 한 층에 들어선 상태예요
`a`는 `int (*)[5]`이니 `*a`로 한 번 따라가면 **0층 그 자체**, 타입 `int[5]`가 나와요. 그런데 이것도 배열이라 다시 붕괴해서 `int *`, 곧 0층 첫 집을 가리켜요. 결국 `*a`는 사실상 `&a[0][0]`이에요 [A p10].

`a[0]`도 같은 원리예요. 실제 타입은 `int[5]`, 식 안에서는 `int *`로 붕괴해 `a[0][0]`을 가리켜요. 원본 예제에서 `(void*)a[0] == (void*)&a[0][0]`을 비교하면 "주소가 같다"가 출력돼요 [A p12]. 차이는 `sizeof`에서 드러나요. `sizeof` 앞에서는 붕괴가 안 일어나니 `sizeof a[0]`은 행 전체인 20, `sizeof &a[0][0]`은 포인터 크기인 8이에요. 또 `&a[0]`은 `int (*)[5]`라서 `&a[0] + 1`은 한 행을 통째로 건너뛰어요 [A p11].

원본의 정리표를 걸음 크기와 함께 보면 다음과 같아요 [A p13–14].

| 식 | 실제 타입 | 붕괴 후 | 걸음 |
|---|---|---|---|
| `&a` | `int (*)[3][5]` | — | 건물 전체 |
| `a` (= `&a[0]`) | `int [3][5]` | `int (*)[5]` | 한 층 |
| `a[0]` (= `&a[0][0]`) | `int [5]` | `int *` | 한 집 |
| `&a[0][0]` | `int *` | 붕괴 없음 | 한 집 |

그럼 이 걸음 크기로 특정 집 `a[i][j]`를 찾아가 볼까요?

## 3. `a[i][j]`를 포인터로 풀어 쓰기

C 표준은 `a[i][j]`를 `*(*(a + i) + j)`로 정의해요 [A p5]. 단계를 따라가 보면 이래요.
1. `a + i`: `a`는 한 층씩 걷는 쪽지라서 i층으로 올라가요.
2. `*(a + i)`: 그 층에 들어서요. 타입은 `int[5]`이고 곧바로 `int *`로 붕괴해 그 층 첫 집을 가리켜요.
3. `*(a + i) + j`: 이제 한 집씩 걷는 쪽지라서 j집 옆으로 가요.
4. `*( … )`: 그 집의 값을 꺼내요.

그래서 다음은 모두 같은 원소예요.
`*(a[i] + j)`, `(*(a + i))[j]`, `*((*(a + i)) + j)`, `*(&a[0][0] + 5*i + j)`

마지막 식은 복도 첫 칸에서 바로 걸어가는 방식이에요. 앞에 i층 × 5집을 지나고 j칸 더 가면 되니까 주소는 이래요.

$$\text{addr}(a[i][j]) = \&a[0][0] + (i \times 5 + j) \times \text{sizeof(int)}$$

> 보충: 예를 들어 `a[1][2]`는 앞에 $1 \times 5 + 2 = 7$칸이 있으니 기준 주소에서 28바이트 뒤예요(int 4바이트 기준).

여기서 열 수 5가 꼭 필요하다는 게 보여요. 그렇다면 이 배열을 다른 함수에 넘길 때는 무엇을 알려 줘야 할까요?

## 4. 2차원 배열을 함수에 넘기기

### 왜 열 크기를 꼭 적어야 할까요?
택배 기사(함수)에게 "1층 2호"를 주려면, 한 층에 몇 집이 있는지 알아야 복도에서 몇 칸 가야 할지 계산할 수 있어요. 그래서 다차원 배열을 형식 매개변수로 선언할 때는 **첫 차원을 뺀 나머지 차원을 모두 적어야** 해요. 컴파일러가 올바른 메모리 매핑을 계산하려면 행 하나의 길이가 필요하기 때문이에요 [A p6].

```c
int sum(int a[][5])          // 열 크기 5는 필수
{ … total += a[i][j]; … }
```

### 매개변수에서는 세 표기가 같아요
배열을 함수에 넘기면 첫 원소 포인터로 붕괴해요. 그래서 매개변수 자리에서는 다음이 모두 같은 뜻이에요 [A p6].
- `int a[][5]` ⇔ `int a[3][5]` ⇔ `int (*a)[5]`
- 1차원도 마찬가지로 `int b[]` ⇔ `int b[3]` ⇔ `int *b`

첫 차원 크기는 강제되지 않아요. `int a[3][5]`라고 적어도 컴파일러는 실제로 넘어온 배열이 3행인지 검사하지 않아요. 행 수가 필요하면 따로 인자로 넘겨야 해요. 열 크기는 생략할 수 없으니 `int a[][]`는 쓸 수 없어요.

그런데 층마다 집 수가 다른 건물이라면 어떻게 할까요?

## 5. 포인터 배열: 건물 주소록

### 왜 필요할까요?
2차원 배열은 모든 층의 집 수가 같아야 해요. 하지만 도담이의 단지에는 5집짜리, 4집짜리 줄이 섞여 있어요. 이럴 때 **주소록**을 만들어요. 주소록 한 줄에는 한 줄(1차원 배열)의 첫 집 주소가 적혀 있어요. 이것이 포인터 배열(array of pointers)이에요 [A p16].

```c
int *parray[3] = {array1, array2, array3};  // 각 배열 이름 = 첫 원소 주소
printf("%5d", parray[i][j]);                // 2차원 배열처럼 사용
```
`parray[i]`는 i번째 쪽지(`int *`)이고, 거기에 `[j]`를 붙이면 그 배열의 j번째 집이에요.

### 줄 길이가 달라도 돼요
각 배열이 따로 있으니 길이가 달라도 상관없어요. 다만 주소록에는 길이가 적혀 있지 않으니 **길이를 따로 보관**해야 해요 [A p17].

```c
int len[3] = {5, 4, 5};
for (j = 0; j < len[i]; j++) …
```

헷갈리기 쉬운 짝이 있어요. `int *p[5]`는 **포인터 5개짜리 배열**(주소록), `int (*p)[5]`는 **int 5개짜리 배열 하나를 가리키는 포인터**(층 단위 쪽지)예요.

이번엔 건물이 여러 동이라면 어떻게 될까요?

## 6. 3차원 배열: 단지 여러 동을 동적으로 짓기

원본은 5×5 크기 이미지 3장을 예로 들어요(`WIDTH 5`, `HEIGHT 5`, `NUM_IMAGES 3`). 동이 3개, 동마다 5층, 층마다 5집인 단지라고 보면 돼요.

### 방법 1: 단계마다 malloc
```c
int **images[NUM_IMAGES];
images[img]    = (int **)malloc(HEIGHT * sizeof(int *));  // 동마다 층 주소록
images[img][i] = (int *)malloc(WIDTH * sizeof(int));      // 층마다 집 5칸
```
타입을 바깥부터 보면 `images`는 `int **[3]`, `images[0]`은 `int *[5]`(층 주소록), `images[0][i]`는 `int[5]`(한 층)이에요. 주소록 3개 + 층 15개로 **malloc 블록이 18개** 생기고, 층끼리는 메모리에서 떨어져 있을 수 있어요 [A p18].

사용할 때는 그냥 3차원 배열처럼 `images[img][i][j]`로 써요. 원본은 `images[img][i][j] = (i + j + img) % 256`으로 채운 뒤 0번 이미지를 출력해서 첫 줄 `0 1 2 3 4`부터 마지막 줄 `4 5 6 7 8`까지 보여 줘요 [A p19].

해제는 **지은 순서의 반대**예요 [A p20]. 층(`images[img][i]`)을 먼저 모두 free하고, 그다음 주소록(`images[img]`)을 free해요. 주소록을 먼저 지우면 층 주소를 잃어버려서 층을 해제할 방법이 사라지기 때문이에요.

### 방법 2: 동마다 한 덩어리로
```c
int (*images[NUM_IMAGES])[WIDTH];   // 행 포인터 3개짜리 배열
images[img] = (int (*)[WIDTH])malloc(sizeof(int) * HEIGHT * WIDTH);
free(images[img]);
```
`images`의 각 원소는 `int (*)[WIDTH]`, 곧 한 층 단위로 걷는 쪽지예요. 전체 타입은 `int (*[3])[5]`예요. malloc으로 HEIGHT × WIDTH개의 int를 **연속된 한 블록**으로 받고, 그 결과를 `int (*)[WIDTH]`로 캐스트해요. 그러면 각 동이 `HEIGHT`행 × `WIDTH`열 2차원 배열처럼 `images[img][i][j]`로 인덱싱돼요. 해제도 동마다 `free` 한 번이면 끝나요 [A p21–23].

방법 1은 블록이 18개로 흩어져 있고, 방법 2는 동마다 연속 블록 하나라서 블록 수가 적어요.
> 보충: 방법 1은 층마다 따로 malloc하니 층마다 길이를 다르게 잡을 수도 있어요.

`int (*images[NUM_IMAGES])[WIDTH]` 같은 선언은 처음 보면 암호 같죠. 이걸 읽는 규칙은 무엇일까요?

## 7. 복잡한 선언 읽기

### 왜 헷갈릴까요?
선언에 붙는 `*`, `[]`, `()`는 연산자와 같은 우선순위로 묶여요. 그래서 먼저 연산자 우선순위를 알아야 해요 [A p25].

| 순위 | 연산자 | 결합 |
|---|---|---|
| 1 | 후위 `++ --`, `()` 함수 호출, `[]` 첨자, `.`, `->`, 복합 리터럴 | 좌 → 우 |
| 2 | 전위 `++ --`, 단항 `+ -`, `! ~`, 캐스트, `*` 역참조, `&` 주소, `sizeof`, `_Alignof` | 우 → 좌 |
| 3–12 | `* / %`, `+ -`, `<< >>`, 관계, `== !=`, `&`, `^`, `\|`, `&&`, `\|\|` | 좌 → 우 |
| 13 | `?:` | 우 → 좌 |
| 14 | `=`와 복합 대입 | 우 → 좌 |
| 15 | `,` | 좌 → 우 |

선언에 필요한 핵심은 **`[]`와 `()`(1순위)가 `*`(2순위)보다 먼저 이름에 붙는다**는 점이에요 [A p27].

### 읽는 규칙
1. 변수 이름에서 시작해요.
2. 오른쪽의 `[]`(배열)나 `()`(함수)를 먼저 읽어요.
3. 그다음 왼쪽의 `*`(포인터)를 읽어요.
4. 괄호가 있으면 괄호 안을 다 읽고 밖으로 나가요.
5. 맨 왼쪽 기본 타입으로 끝내요.

### 기본 예
- `char **argv`: char 포인터를 가리키는 포인터
- `int (*daytab)[13]`: 괄호 때문에 `*`가 먼저 → int 13개 배열을 가리키는 포인터
- `int *daytab[13]`: `[13]`이 먼저 → int 포인터 13개짜리 배열 [A p26]
- `int array[3][4]`: 타입은 `int[3][4]`(int 4개 배열 3개), 대부분 식에서 `int (*)[4]`로 붕괴 [A p26]
- `void *comp()`: `()`가 먼저 → void 포인터를 반환하는 함수
- `void (*comp)()`: `*`가 먼저 → void를 반환하는 함수를 가리키는 포인터
- `void (*comp[3])()`: 배열 3개 → 각각 포인터 → void 반환 함수 [A p27]

### 대표 문제: `char (*(*comp[3])(void))[5]`
원본의 단계 그대로 따라가요 [A p29].
1. `comp`: 이름에서 시작해요.
2. `comp[3]`: `[]`가 먼저 붙으니 3칸짜리 배열이에요.
3. `(*comp[3])`: 괄호 안 남은 `*` → 포인터 3개의 배열이에요.
4. `(*comp[3])(void)`: 괄호 밖 오른쪽 `()` → 함수를 가리키는 포인터들이에요.
5. `*(*comp[3])(void)`: 왼쪽 `*` → 그 함수는 포인터를 반환해요.
6. `(…)[5]`: 그 포인터는 5칸 배열을 가리켜요.
7. `char`: 배열 원소는 char예요.

결론: **char 5개 배열의 포인터를 반환하는 함수, 그 함수를 가리키는 포인터 3개짜리 배열**이에요. typedef로 나누면 훨씬 읽기 쉬워요 [A p28].
```c
typedef char CharArray5[5];
typedef CharArray5 *Func(void);
Func *comp[3];
```

### 함수는 배열을 반환할 수 없어요
같은 재료로 다른 모양을 만들면 오류가 나요 [A p28].
- `char ((*comp[3])(void))[5]`: 함수가 char 5개 **배열**을 반환하는 모양 → 오류
- `char f()[10];`: 함수가 배열 반환 → 오류
- `char *(*comp[3])(void)[5]`: 함수가 char 포인터 5개 **배열**을 반환 → 오류

배열을 돌려주고 싶으면 위처럼 **배열을 가리키는 포인터**를 반환해야 해요.

### 하나 더: `char (*(*x())[])()`
이번엔 이름 바로 뒤가 `()`예요 [A p30]. `x()` 함수 → `(*x())` 포인터를 반환 → `[]` 배열을 가리킴 → `*` 그 배열 원소는 포인터 → `()` 함수를 가리킴 → `char` 반환. 곧 **char를 반환하는 함수들의 포인터 배열, 그 배열을 가리키는 포인터를 반환하는 함수**예요. 크기 없는 `[]`는 크기 미지정 배열이고, 그런 배열을 가리키는 포인터는 허용돼요.
```c
typedef char (*CharFuncPtr)(void);   // char 반환 함수 포인터
typedef CharFuncPtr FuncPtrArray[];  // 그 포인터들의 배열(크기 미지정)
FuncPtrArray *x(void);               // 그 배열의 포인터를 반환하는 함수
```

함수를 가리키는 포인터가 이렇게 자주 나오는데, 실제로는 어디에 쓸까요?

## 8. 함수 포인터: 줄 세우기 기준을 건네주기

### 왜 필요할까요?
도담이가 주민을 줄 세워야 해요. 어떤 날은 숫자 순, 어떤 날은 성적 순이에요. 줄 세우는 방법(정렬 알고리즘)은 같고 **누가 앞인지 판정하는 기준**만 바뀌죠. 그래서 정렬 함수에 "판정 담당자"의 주소, 곧 **함수 포인터(pointer to function)** 를 건네줘요.

### 퀵정렬
퀵정렬(quicksort)은 Tony Hoare가 1959년에 만든 빠른 분할 정복(divide-and-conquer) 정렬이에요 [A p32].
1. 배열에서 피벗(pivot) 하나를 골라요.
2. 피벗보다 작은 원소와, 크거나 같은 원소로 두 부분을 나눠요.
3. 두 부분을 각각 재귀로 정렬해요.

C 표준 라이브러리 `<stdlib.h>`에는 퀵정렬에서 이름을 딴 `qsort`가 있어요. 이름만 그렇고, 표준이 실제 알고리즘을 정하지는 않아요.
```c
void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));
```
시작 주소, 원소 개수, 원소 하나의 크기, 그리고 비교 함수 포인터를 받아요.

### 강의의 quicksort 따라가기
```c
void quicksort(void *v[], int left, int right,
               int (*comp)(const void *, const void *))
{
    if (left >= right) return;            // 원소 0~1개면 끝
    swap(v, left, (left+right)/2);        // 가운데를 피벗으로 맨 앞에
    last = left;
    for (i = left + 1; i <= right; i++)
        if (comp(v[i], v[left]) < 0)      // 피벗보다 작으면
            swap(v, ++last, i);           // 작은 구역 끝에 붙임
    swap(v, left, last);                  // 피벗을 경계로 옮김
    quicksort(v, left, last - 1, comp);
    quicksort(v, last + 1, right, comp);
}
```
`swap`은 `void *` 두 칸을 임시 변수로 맞바꿔요. 원소 타입을 모르니 모든 원소를 `void *`로 다루고, 비교만 `comp`에게 맡기는 구조예요 [A p33].

원본 그림으로 한 번 분할해 봐요 [A p32–33]. 배열 `3 7 8 5 2 1 9 5 4`
1. 가운데 원소 2가 피벗이에요. `swap(v, left, (left+right)/2)` → `2 7 8 5 3 1 9 5 4`
2. i를 오른쪽으로 옮기며 비교해요. 1 < 2라서 `swap(v, ++last, i)` → `2 1 8 5 3 7 9 5 4`. 이제 `[피벗 | 2보다 작은 구역(last까지) | 2 이상 구역 | 아직 안 본 구역(i부터)]`으로 나뉘어 있어요.
3. 끝까지 본 뒤 `swap(v, left, last)` → `1 2 8 5 3 7 9 5 4`. 피벗 2가 제자리에 섰어요.
4. 2의 양쪽을 재귀 정렬하면 `1 2 3 4 5 5 7 8 9`가 돼요.

### 비교 함수 만들기
비교 함수 규칙은 앞이 작으면 음수, 크면 양수, 같으면 0이에요. 문자열을 숫자로 보고 비교하는 `numcmp`는 이래요 [A p34].
```c
v1 = atof((const char *)s1);
v2 = atof((const char *)s2);
if (v1 < v2) return -1; else if (v1 > v2) return 1; else return 0;
```
사용할 때는 `quicksort` 호출에 함수 이름 `numcmp`를 그대로 넘겨요 [A p35].
> 보충: 함수 이름도 배열 이름처럼 식 안에서 그 함수의 주소로 바뀌어서, 이름만 넘겨도 함수 포인터 매개변수에 들어가요.
```c
char *arr[] = {"10.1", "8.2", "100.3", "2.1", "5.5"};
v[i] = arr[i];                    // void * 배열에 복사
quicksort(v, 0, n - 1, numcmp);   // 판정 담당자 전달
printf("%s ", (char *)v[i]);      // 꺼낼 때 원래 타입으로
```
> 보충: 숫자 기준이라 결과는 `2.1 5.5 8.2 10.1 100.3` 순서가 돼요. 문자열 사전 순이었다면 "100.3"이 "2.1"보다 앞에 왔을 거예요.

### 함정: 비교 함수가 무엇을 받나요?
강의의 `quicksort`는 원소 자체 `v[i]`를 넘겨요. 원소가 문자열 포인터이니 `s1`이 곧 문자열이고 `(const char *)s1`이 맞아요. 반면 **표준 `qsort`는 원소를 가리키는 포인터**를 넘겨요. 문자열 배열이면 `s1`은 "char 포인터를 가리키는 포인터"라서, `qsort`에 쓰려면 이렇게 바꿔야 해요 [A p34].
```c
v1 = atof(*(const char **)s1);
v2 = atof(*(const char **)s2);
```

### 기준만 바꾸면 다른 줄이 돼요
학생 구조체(`char name[50]; double grade;`)를 성적순으로 세우는 `compare_students`는 표준 `qsort` 규약을 따라요 [A p36]. 받은 포인터가 학생 원소를 가리키니 `const student *`로 바꿔 `grade`를 비교해요.
```c
const student *student_a = (const student *)a;
if (student_a->grade < student_b->grade) return -1; …
```
> 보충: 호출은 `qsort(students, 5, sizeof(student), compare_students);` 모양이 돼요.

줄 세우기를 끝낸 도담이가 이번엔 단지 게시판에 손을 대려고 해요. 그런데 어떤 글은 고칠 수 있고 어떤 글은 고칠 수 없어요. 왜 그럴까요?

## 9. 문자열과 포인터: 게시판 공고와 내 집 메모판

### 두 선언의 차이
문자열 리터럴(string literal) `"apple"`은 단지 **게시판에 붙은 공고**와 같아요. 누구나 읽을 수 있지만 고칠 수는 없어요 [A p38].
- `char *pc = "apple";`: 스택에는 **쪽지(포인터, 8바이트)만** 있고, 글자들은 읽기 전용 영역(게시판)에 있어요. 그래서 `pc[0] = 't'`는 정의되지 않은 동작이에요.
- `char str[50] = "apple";`: 50바이트 전부를 str이 소유하는 **내 집 메모판**이에요. 초기화하면서 글자를 복사해 오니 `str[0] = 't'`는 괜찮아요. 하지만 이름 `str` 자체에는 다른 것을 대입할 수 없어요.

| 항목 | `char *pc` | `char str[50]` |
|---|---|---|
| 대입 | `pc = "banana";` 가능(다른 공고를 가리킴) | `strcpy(str, "banana");`로 복사 (`str = "banana";`는 오류) |
| 크기 | `sizeof(pc)` 8(32비트는 4) | `sizeof(str)` 50 |
| 수정 | `pc[0] = 't';` UB | `str[0] = 't';` 가능 |
| 입력 | `scanf("%s", pc);` UB | `scanf("%49s", str);` 최대 49자 + `'\0'` |

[A p39]

### 리터럴도 배열 이름처럼 쓰여요
문자열 상수는 배열 이름처럼 첫 글자 포인터로 취급돼요 [A p40].
```c
*"apple"        // 'a'
*("apple" + 1)  // 'p' (포인터 연산)
"apple"[2]      // 'p' (배열식 접근)
```

### 단지 지도: 메모리 배치
게시판이 따로 있다는 게 무슨 뜻인지 32비트 x86 Linux의 메모리 지도로 보면 분명해져요 [A p41]. 높은 주소부터 보면 이래요.
- **커널 공간**(0xC0000000–0xFFFFFFFF, 1GB): 사용자 코드는 접근할 수 없어요. 나머지 3GB가 프로그램 몫이에요.
- **스택**(아래로 자람): 지역 변수, 반환 주소. `pc`, `str`이 여기 있어요.
- **메모리 매핑 영역**: 공유 라이브러리, mmap.
- **힙**(위로 자람): malloc/free로 받는 곳. 6절의 `images`가 여기 지어져요.
- **BSS**: 초기화하지 않은 정적 변수.
- **Data**: 초기화한 정적 변수.
- **읽기 전용 데이터**: 문자열 리터럴, const 전역 변수. 바로 게시판이에요.
- **Text(코드 영역, 0x08048000부터)**: 기계어 명령.
- **예약 영역**(0x00000000 근처): 매핑되지 않아서 NULL 포인터에 접근하면 여기서 오류가 나요.

간단한 그림에서는 Text를 "기계어, 읽기 전용"으로 묶고, 자세한 그림에서 메모리 매핑 영역과 읽기 전용 데이터 영역을 따로 보여 줘요.

이제 주민이 메모판에 직접 글을 써 넣는 입력 이야기로 넘어가요. 메모판보다 긴 글이 들어오면 어떻게 될까요?

## 10. 안전한 문자열 입력

### scanf의 위험
`scanf("%s", buffer)`는 기본적으로 입력 길이를 검사하지 않아요. 메모판보다 긴 글이 들어오면 메모판 밖 이웃 메모리까지 덮어써요. 이것이 버퍼 오버플로(buffer overflow)예요 [A p42].

### 더 안전한 방법
```c
fgets(buffer, SIZE, stdin);
scanf("%79s", buffer);   // SIZE - 1 = 79, 마지막 칸은 '\0' 자리
getline(…);              // 아래에서 설명
```
fgets와 `%79s`는 오버플로가 생기지 않아요. 다만 다 못 읽은 문자는 입력 버퍼에 남아서 **다음 입력 함수가 읽어 가요**. 반복문에서 여러 문자열을 읽으면 이 때문에 엉뚱한 값이 들어와 혼란이 생겨요. C에는 입력 버퍼를 비우는 표준 함수가 없으니 직접 버려요 [A p42].
```c
while ((ch = getchar()) != '\n' && ch != EOF)
    ;  // 줄 끝까지 버림
```

### `%79s`는 단어 하나만 읽어요
`scanf("%79s", str)`는 공백으로 구분된 토큰 하나만 읽어요. "Jessica Kim"을 입력하면 첫 호출은 `Jessica`, 두 번째 호출은 남아 있던 `Kim`을 읽어요 [A p43]. 두 번째 호출 뒤 메모리는 `K i m \0 i c a \0 …`처럼 앞 단어의 흔적 "ica\0"이 남아 있어요. 그래도 printf는 첫 `'\0'`에서 멈추니 `Kim`만 출력돼요.

### getline: 크기를 알아서 맞춰 주는 입력
줄 길이를 미리 모를 때는 getline이 편해요 [A p44].
```c
ssize_t getline(char **lineptr, size_t *n, FILE *stream);

char *buffer = NULL;  size_t size = 0;  ssize_t len;
len = getline(&buffer, &size, stdin);
if (len != -1) printf("You typed: %s", buffer);
free(buffer);
```
버퍼 주소와 크기를 **포인터로** 넘기는 이유는 getline이 그 값을 바꿔야 하기 때문이에요.
- `buffer`가 NULL이면 알맞은 크기로 malloc하고, 크기를 `size`에, 포인터를 `buffer`에 넣어요.
- stdin에서 한 줄 전체를 끝의 `'\n'`까지 읽어요(EOF로 끝나면 개행 없음).
- 줄이 현재 버퍼보다 길면 버퍼를 다시 할당하고 `size`를 갱신해요.
- 반환값은 읽은 문자 수예요. 개행은 포함하고 `'\0'`은 빼요. 아무것도 못 읽었거나(EOF) 오류면 −1이에요.
- `ssize_t`는 −1을 담을 수 있는 부호 있는 크기 타입(POSIX)이에요.

다 쓰면 `free(buffer)`를 꼭 해요. −1을 반환했어도 이미 버퍼를 할당했을 수 있어요. 또 getline은 표준 C가 아니라 POSIX(Portable Operating System Interface) 함수라서 Linux, macOS 같은 유닉스 계열에는 있지만 Windows의 MSVC에는 없어요.

## 한눈에 이어 보기
- 다차원 배열(한 줄 복도, 행 우선) → 배열 붕괴 → 쪽지 타입마다 걸음 크기(`int *` 한 집, `int (*)[5]` 한 층, `&a` 건물 전체) → `a[i][j] = *(*(a+i)+j)`와 주소 공식
- 열 크기가 있어야 주소 계산 → 함수 매개변수는 첫 차원만 생략 가능(`int (*a)[5]`)
- 행 길이가 다르면 포인터 배열 + 길이 배열 → 여러 동은 3차원 동적 할당(단계별 malloc, 역순 free 또는 행 포인터로 한 덩어리)
- `[]`·`()`가 `*`보다 먼저 → 복잡한 선언 해석, 함수는 배열 대신 배열 포인터 반환 → 함수 포인터로 비교 기준 전달(quicksort, qsort는 원소의 포인터를 넘김)
- 리터럴은 읽기 전용 영역, 배열은 내 사본 → 입력은 길이 제한(`%79s`, fgets) + 남은 문자 비우기, 길이를 모르면 getline 후 free
